# Gotchas: Navidrome API & Credentials

## Credentials

- **The Subsonic credential is opaque**: it is the token pair (`u=…&s=…&t=…`) or an API key (`apiKey=…`, `services/api_key.rs`). Never read the username out of it (`AuthGateway::username()`, or the stored `SessionOwner`), never add `u`/`p`/`t`/`s`/`jwt` to a `/rest` request (beside a key the server answers error 43, and Navidrome merges a form body into the query before it checks), send any URL that carries it to a log through `redact_subsonic_url`, and turn a `reqwest::Error` from such a request into text only after `without_url()` (its message embeds the URL; `send_scrobble` is the pattern). Codes 40, 41, 42 and 44 mean the credential is dead and drop to login (`check_subsonic_response_status`). The builders' twin is `CredentialParts::parse` (`services/auth.rs`, beside `subsonic_token_credential`: form-decoded salt, token and apiKey, with no username field on purpose); read a credential through it. Usernames compare with `same_user` and key with `user_key` (case-insensitive, as Navidrome's `COLLATE NOCASE` lookup), never an inline `to_lowercase`.
- **Nothing sends the credential before the session check**: Navidrome 0.64.1+ locks a user out from one address after 5 failed `/rest` logins in 20 s and then answers every request, correct password too, with the same error 40 (`auth_limiter.go`). So `finish_login` (`update/navigation.rs`) checks the session before `LoginSuccess` lets the home screen's first burst out (#14): a resume asks the native keepalive (`AuthGateway::check_token`, outside the limiter), then one strict ping (`check_credential`) unless the keepalive refused, also when it gave no verdict (a proxy error page, a slow first connection), and a refusal ends the saved session on the login form, keeping a password typed meanwhile (`LoginPage::on_session_ended`); a password login pings after its key step, reads an error 40 there as the lockout, tells the form (`LoginProgress`) and waits it out (`wait_out_lockout`). Only a ping without a verdict (unreachable, a timeout) goes ahead unchecked. A new request on the resume or login path goes after the check.
- **A client that sends the Navidrome credential sets a redirect policy** (`utils::redirects`): reqwest's default follows a 307/308 to any host, sending the body (a `/rest` form, the login's password, a new API key) and custom headers like `X-ND-Authorization` again. `server_only()` for a client that only talks to the server (API client, login, SSE, covers); `guard_credential_urls()` for one that also fetches other hosts (the audio decoder and range reader play stations, which redirect freely). A refused hop comes back as the 3xx answer.

## Library semantics

- **A one-off random draw must never use `_sort=random`**: Navidrome re-seeds its per-`(table, user)` seeded-random ordering for every query it maps to `Sort: "random"` arriving at `Offset == 0` (`resetSeededRandom`, `persistence/sql_base_repository.go`) — so a background draw silently re-permutes an in-progress Albums/Songs **Random**-sort pagination in the browse views (already-scrolled rows reappear, others are skipped). Passing an explicit `seed` does not help; that branch calls `SetSeed` on the same shared key, and the Subsonic `getAlbumList{,2}&type=random` endpoints route through the identical path. The two safe draws: **songs** → Subsonic `getRandomSongs` (`services/api/random.rs`; `ORDER BY random()` over rowids, touches no shared seed), **albums/artists** → `pagination::draw_random_row` (count-probe + random offset over the stable `RANDOM_DRAW_SORT`). Genres/playlists shuffle client-side, so their `"random"` is a no-op on the wire. Invisible to CI and to a single-view smoke test — it only shows up when one view paginates Random while another draws.
- **Genre identity — name vs tag id**: a server genre's `Genre::id` (from `/api/genre`) is a **tag id** (a hash of the lowercased value), NOT the name. Each wire key takes exactly one of the two. **`genre_id` carries the tag id**: on `/api/album` and `/api/song` it is an indexed `tag_id = ?` join since Navidrome 0.64 (`genreFilter` in `persistence/sql_tags.go`), so a name there returns HTTP 200 with zero rows and no error. `LibraryFilter::GenreId` pushes its `id`, `GenreUIViewData::songs_filter()` builds the Songs-view filter, and `load_genre_albums{,_full}` and `load_songs_by_genre` take the id. Plays, queue adds and Trawl seeds carry a `GenreRef { id, name }` (`BatchItem::Genre` / `SongSource::Genre`), built only from an `/api/genre` row (`GenreUIViewData::genre_ref()`, `GenreRef::from(&Genre)`): they fetch by the id, label with the name, and the Trawl crate keys a genre seed on the id. Avoid the bare `genre=<name>` key on `/api/song`: it is an unindexed, exact-case `json_tree` match, so it misses the other casings a Genres row counts. **Subsonic `getRandomSongs?genre=`** carries the name. Everywhere else the client identity is the **NAME**: `PlayTarget::GenreRandom` / `PendingExpand::Genre { genre_name }` (the click sites hold only the row's genre text) / Harbour's fan-out results and collage/side-map keys. Harbour's quad fan-out takes `(name, tag id)` pairs, requests by id and keys the reply by name. Its Most Played genres are tallied from song `genre` strings, so `stamp_tally_genre_ids` stamps their tag id from the `/api/genre` list (exact name, then a lowercased match); a miss keeps `id == name` and that quad stays blank on 0.64+. The one id-keyed cache is the Genres view's collage pipeline (`handle_load_genre_collage` → `LoadCollage` → cache + `library.genres` row match), which is self-consistent end-to-end — keep it whole or convert it whole, never mix keys within a surface. Related caveat: Subsonic `getRandomSongs?genre=` matches via SQL `LIKE`, so a name containing `%`/`_` over-matches and matching is case-insensitive for ASCII letters only (SQLite's default `LIKE` does not case-fold non-ASCII, and Navidrome registers no ICU/custom LIKE) — never case-normalize a genre name client-side; send the server-canonical name verbatim. `getRandomSongs` / `getSimilarSongs2` / `getTopSongs` return Subsonic `Child` objects, which have **no `compilation` field** (only albums expose `isCompilation`) and spell the album artist `displayAlbumArtist` (aliased onto `Song::album_artist`, which is what keeps the crossfade album-continuity policy's Various-Artists escape alive). Any policy reading `Song.compilation` degrades silently on those paths — check `crossfade_policy.rs` before adding one.
