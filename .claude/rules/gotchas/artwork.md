# Gotchas: Artwork

- **Version-aware refetch + negative cache**: the prefetch gates run through `should_refetch(cached_ids, versions, failed, id, version)`. The version is `artwork_version(&image, updated_at)` (`data/src/types/image_info.rs`): the entity's `imageHash` when a Navidrome 0.64+ server sends a valid one, else `updated_at` as on older servers. `build_cover_art_url_with_timestamp` puts a hash on the id (`al-<id>_<hash>`, no `_u=`) and a timestamp in `_u=`, so an old server's URLs and versions stay byte-identical. `ArtworkState.album_art_versions` (album-id → the version that warmed each slot) lets album-coherent surfaces (Albums view, Artists/Genres expansion and Harbour shelves via `album_prefetch_entry`; the `ar-` artist minis of the Artists view, Harbour and the Trawl search via `artist_art_entry` and the shared `artist_mini_task`) re-fetch when the server cover changes; with a hash that is exactly when the image bytes change, never on a play-count bump. Art the server marks `imageAbsent` is never requested by a surface that holds the entity (the album projection builds no URL; artist, large-art and Refresh paths check `album_image_absent` / `artist_image_absent`), and nothing is negative-cached for it, so a reload that clears the flag fetches normally. Passive surfaces (queue, song-mini, similar, playlist editor) carry only a per-song `updated_at` that would oscillate the album-id-keyed map, so they feed a constant `None` via `passive_artwork_version()` (id-only dedup). `ArtworkState.failed_art` is the negative cache: album/artist ids whose 80px fetch returned NO image (code-70 "Artwork not found" — an album that merely lacks a cover gets a placeholder *image* and caches normally, so it never lands here). Membership stops re-queuing a known-dead id on every scroll/resize/view-switch; a CHANGED `updated_at` bypasses the entry and re-attempts. Both maps are unbounded but reset wholesale by `ArtworkState::default()` on logout, so server-A failures never suppress server-B art.
- **Always `Handle::from_bytes`**: `from_bytes` allocates a fresh `Id::Unique` per call — safe **only** because Handles are stored in the LRUs and reused across renders. Never re-create from bytes per frame; that bypasses Iced's GPU texture cache (`reference-iced/wgpu/src/image/raster.rs:55`).
- **Snapshot mirrors**: `view()` borrows the `HashMap` snapshot inside each `SnapshottedLru`, not the LRU directly, because LRU `get` is `&mut`. The newtype keeps both in sync on every `put` / `get_touch` promotion; no caller-side discipline needed.
- **Every 80px fetch gates on `album_art_pending` and claims what it sends**: the viewport prefetches re-run on every scroll step and the fan-outs on every re-entry, and a gate on arrived thumbnails alone re-requested every thumbnail still on its way per step (one thumbnail was fetched 29 times against the one-core demo server; the repeats queued ahead of the large covers, the media-widget cover and the audio). The planners in `src/update/components/artwork_prefetch.rs` (`prefetch_album_artwork_tasks`, `prefetch_song_artwork_tasks`, `expansion_album_artwork_tasks`, the quad warmers) take an `ArtworkGate` (`ArtworkGate::new(&self.artwork)`: the warm ids, their versions, `failed_art` and the pending set) and return `(queued_ids, tasks)`; the CALLER drops the gate and claims the ids after its borrows end (the `drop(gate)` + `self.claim_minis(queued)` tail), because `rows` from `filter_queue_songs()` borrow all of `self`. `Nokkvi::claim_minis` is the one claim: it also decodes each id's ThumbHash (Navidrome 0.64+, `thumb_hash_of`) into `ArtworkState::placeholders`, the blur a row (`views::mini_or_placeholder`) and the big panel (`views::panel_cover`) draw until the cover lands, and `every_mini_claim_goes_through_claim_minis` fails on a hand-written `album_art_pending` claim. The `ar-` artist minis go through Harbour's `artist_minis_to_warm` / `artist_mini_warm_tasks` (the Artists viewport included), station logos through `radio_art_pending`, and the now-playing warm checks the set in `now_playing_artwork_to_warm`. `handle_artwork_loaded` / `handle_song_artwork_loaded` / `handle_radio_art_loaded` release on success and failure alike, so a transient failure is re-attempted by the next pass as before. Claim AFTER the planner has seen the set: `strip_quad_prefetch_tasks` once inserted first and so filtered out everything it had just planned. A new 80px path consults, claims through `claim_minis` and releases; each surface has an `*_in_flight_are_not_requested_again` test.
- **A navigation step's big-panel cover goes through `Nokkvi::panel_art_step`** (`PanelArtSettle`, `src/state/artwork.rs`): a lone step loads at once, a step within `PANEL_ART_RUN_GAP` of the last waits, and only the row a run stops on loads, `PANEL_ART_SETTLE` later (`PanelArtSettled`), so an 80-row scroll fetches one 1 MB cover instead of 80 that queued ahead of the thumbnails. A cached cover never waits. The Albums, Artists (`artist_step_tasks`), Songs, Similar, Queue (via `PanelArtStep`, it borrows the rows), Harbour and editor steps use it; a load with another trigger (view switch, expand, a page landing, the playing song) calls its loader directly. The panel shows the thumbnail or the placeholder meanwhile (`views::panel_cover`). The timer's `tokio::time::sleep` is made inside the task's `async` block, because building it outside a runtime panics (handler tests have none).
- **Large-art fetches gate on an in-flight map keyed by version**: every centering re-dispatches the panel's large-art load, and a held arrow key at a list's end re-centers the same row ~25x/s; on a slow server that stacked hundreds of full-size requests for one cover and starved the audio stream. `large_artwork_pending` (albums + artists), `radio_large_art_pending` and `playlist_custom_large_art_pending` are `InFlight<V>` gates (`src/state/artwork.rs`) mapping id -> the version the request carries: `holds` an exact repeat (it sends nothing), a changed version goes out (so the gate never pins a replaced cover). `claim` only once the fetch task is built (after the `app_service` check: artwork state resets at logout, not login), `release` in the `*Loaded` handler on every outcome, and `forget` wherever a cover's cache is cleared for a re-warm (`clear_radio_station_art_handles`, `clear_playlist_custom_art`). The station-logo and custom-cover minis (`radio_art_pending`, `playlist_custom_art_pending`) are `InFlight<()>`, gated with `contains`. A new gated path does all four. A `forget` does not stop the old fetch: its completion still releases and stores what it fetched. `loading_large_artwork` is only the latest-request marker, not a gate.
- **Frozen strip quad identity**: the queue strip's playlist quad renders from `strip_quad_album_ids`, snapshotted via `snapshot_strip_quad_ids()` on the FIRST queue load for the active playlist context (`handle_queue_loaded`) — at that moment queue order == playlist track order. Later queue reloads (consume advance, sort, SSE) intentionally leave the frozen ids untouched so prefetch and render agree on identity; `clear_active_playlist()` drops the snapshot with the context so the next playlist re-freezes from its own queue head.
- **SSE refreshes covers only through the reload**: a `LibraryChanged` event (wildcard or id-anchored) reloads the slot lists and triggers no artwork refresh of its own; a blanket re-fetch would re-download every cached cover. The post-load viewport prefetch then refetches only rows whose version changed, which with Navidrome 0.64 image hashes is exactly the changed covers, and `handle_artwork_loaded` drops the stale large art when a mini arrives at the rows' current hash while `ArtworkState.large_artwork_hashes` says the large art was requested at a different one. That map is separate from `album_art_versions` because the passive surfaces write `None` there, and the current-row check keeps a surface refetching an old hash from dropping the right image. Older servers send no hashes, so it never fires there.
- **Random-sort SSE protection**: background SSE reload mustn't corrupt the artwork ref when the active sort is Random — guarded in `library_refresh.rs`.
