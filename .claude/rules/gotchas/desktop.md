# Gotchas: Desktop Integration (MPRIS, tray, IPC, launch)

- **MPRIS art is always present for a current item**: while a song or station is current and the cache dir is writable, `resolve_art_for_mpris` (`services/mpris_art_writer.rs`) always publishes `mpris:artUrl`, falling back to the app-icon placeholder, because shells keep the previous image when the key is absent. A failed cover or placeholder is retried after `RETRY_FAILED_AFTER` (60 s), never per tick: a station's logo token never changes while it plays, so no track change would retry it. Cover ids and station logos go through the writer as `file://` cache paths, so no credentialed `getCoverArt` URL reaches D-Bus. ICY `StreamUrl`s are published raw and only when http(s). The tick resolves this art before every state update, so it only fetches from the user's own server, never from a station's image host; the cover fetch runs on its own task and the tick waits at most `COVER_WAIT` (500 ms) for it, then publishes the placeholder and a later tick swaps the cover in (`ArtCacheState::in_flight`; a song change drops and aborts it). A slow server once held the whole update, title included, for as long as the cover took. The writer's lock is held across that wait on purpose: the ticks queue behind it in order.
- **MPRIS multi-instance bus name**: nokkvi suffixes its bus name with `instance{pid}` (per the MPRIS spec) so two running instances don't silently fight over `org.mpris.MediaPlayer2.nokkvi` — without the suffix the loser of the race ends up with no MPRIS at all and nothing logs it. Don't drop the suffix.
- **The launch lock comes before the socket probe** (`nokkvi_ipc::instance_lock`, `second_launch_action` in `src/main.rs`): the IPC socket binds seconds into boot, so two near-simultaneous launches both saw no socket and both booted. Every launch past the argv gate takes an exclusive `flock` on `nokkvi.lock` in the socket dir and the winner holds it until `main` returns; a loser does not boot while the lock is held (a bare one waits up to 15 s for the socket and forwards `show`, boots if the lock comes free first because the holder crashed or quit, else refuses) and exits before tracing truncates the log or iced starts MPRIS and the tray. The `nokkvi <verb>` client path never takes the lock, and the lock file is never deleted.
- **MPRIS describes one item per tick, and `SetPosition` is judged against it**: the tick's MPRIS push records `Nokkvi.mpris_track` (`PublishedTrack`: the `mpris:trackid` from `track_id_path`, the length, `CanSeek`, true only for a playing or paused queue song of known length that the engine can seek (not a live transcode); sent with every current tick, the crate drops repeats) and publishes metadata only when `tick_matches_active_item` says the tick was built for the item playing now. `SetPosition` seeks only through `PublishedTrack::set_position_target` (current id, `0..=length`, CanSeek) and a relative `Seek` only while CanSeek holds, per the spec. Keep the id escaping injective: a lossy one lets a stale `SetPosition` seek another track.
- **A service on its own thread must end with its subscription**, not only when its command channel closes: the app keeps the `*Connection` handle it got from `Connected` after the feature is switched off, so that channel never closes. The tray thread checks its event sender's `is_closed()` in `pump_commands` (`services/tray.rs`); without it, turning Show Tray Icon off left a dead icon behind. Services that run inside the subscription future (notifications) are torn down with it and need nothing.
