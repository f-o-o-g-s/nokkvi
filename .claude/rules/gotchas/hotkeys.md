# Gotchas: Hotkeys

- **Global hotkeys are suppressed on the login screen**: `handle_raw_key_event` early-returns when `screen == Screen::Login`. The login form owns its own keyboard (Tab focus + Enter on_submit); without the guard the always-on keyboard subscription double-dispatches — Tab is whitelisted past the capture guard and resolves to `SlotList(NavigateDown)` against the off-screen queue (firing the Tab SFX twice, churning hidden selection), and bare `x`/`c` toggle random/consume against an idle engine. Leave the `event::listen_with` subscription intact (reverting it reintroduces the swallowed Escape/Enter regression).
- **Bare modifier/lock keydowns are dropped**: `handle_raw_key_event` drops bare Shift/Ctrl/Alt/Super/CapsLock keydowns AFTER the hotkey-capture forward and BEFORE dispatch. They resolve to no hotkey, but otherwise a bare Shift arrives `Status::Ignored` and trips the smart-playlist rules editor's Editing-mode focus-loss grammar — committing + blurring the cell so the following typed capital leaks to a global hotkey (Shift+S = FindSimilar, Shift+D = ClearQueue). Placement after the capture forward is load-bearing so chord rebinding still sees the modifiers.
- **Shared key combos resolve deterministically**: `HotkeyConfig::lookup` and `find_conflict` share one `resolve` — a RESERVED action, then a configurable action whose binding differs from its default (the user put it there), then declaration order. Never iterate the `bindings` HashMap to pick a winner.
- **Moving a hotkey default means adding a `RETIRED_DEFAULTS` row** (`data/src/types/hotkey_config/config.rs`) in the same commit. `normalize` then moves an action still sitting on its retired default to the new one — but only when the retired combo is contested AND the new default is free, so it can never strand an action on a key another binding already wins. Startup rewrites `[hotkeys]` once when it changed something; the hot-reload path never writes (config-watcher feedback loop).
- **A TV remote's OK and Back become Enter and Escape before anything reads the key**: OK (`KEY_SELECT` / `KEY_OK`, which iced reports as `Key::Unidentified` because winit doesn't map `XF86Select`) in the keyboard subscription (`hotkeys::remote_key_alias`, `src/hotkeys/remote.rs`, called from `subscription()` in `src/main.rs`), Back (`BrowserBack`) at the top of `handle_raw_key_event` (`is_remote_back`), ahead of the hotkey capture. So every literal Enter / Escape check (modal gate, rules editor, theater, capture cancel) covers the remote with no per-site code. Back keeps one difference, swapped in at the final dispatch: `ClearSearch` becomes `RemoteBack` (`handle_back(true)`), which with nothing left to back out of highlights the tabs instead of reloading; never for a Captured press (an overlay menu just took it to close). A key iced can't name rides on `RawKeyEvent` (and `HotkeyCaptured`) as its Linux code (`unnamed_key_code`) and binds as `KeyCode::Native` ("Key 582"); a handler that re-runs a raw key passes the code along.
- **Media keys and a remote's Home key are RESERVED actions** (`MediaPlayPause`, `MediaPause`, `MediaStop`, `MediaNextTrack`, `MediaPreviousTrack`, `GoHome` → Harbour), so a capture can't take their keys. Theater passes the five transport ones through (`GoHome` exits, then switches), and every modal takes them (`MEDIA_KEY_ACTIONS`, `update/modals.rs`). A desktop that grabs them (Plasma, GNOME, a compositor bind) never delivers them; MPRIS carries the press instead.
- **Focus Navigation highlights the nav bar** (`Nokkvi.nav_focus: Option<NavFocus>`, default key Menu, which a remote's `KEY_COMPOSE` and `KEY_MENU` both become): while it is set, `nav_focus_key_intercept` (`update/hotkeys/navigation.rs`) takes the LITERAL arrows, Enter and Escape ahead of the rules editor and the view, with no root modal on top and outside theater. The bar's own arrows walk `NavFocus::ORDER` (Left/Right on the top bar, Up/Down on the sidebar: the pure `nav_focus_key`), Enter opens through the same `SwitchView` a click sends, the arrow toward the list or Escape leaves, and any other key drops the highlight and runs as usual. Every view switch and theater entry clears it, and so does `reset_session_state`. The None layout has no bar: the action toasts instead. Plasma Bigscreen keeps the Menu key for its app switcher, which is why a remote's Back at rest is the other way in (above).
- **Bare Up/Down move the list outside Settings**: `EditUp` / `EditDown` are no-ops nowhere. `handle_edit_value` edits Settings only with no root modal on top, else dispatches `SlotListMessage::NavigateUp/Down` synchronously, and `ActiveModal::takes_action` counts them as list keys. That is what lets a remote's D-pad (arrows + OK, no Tab) scroll the library.
