# Visualizer

## SpectrumEngine (RustFFT)

Pure-Rust FFT in `data/src/audio/spectrum.rs`. Dual-band FFT (bass 2×, treble 1×). `max_bars_for_sample_rate()` caps treble bins; `interpolate_bars()` (`src/widgets/visualizer/state.rs`) fills gaps. Zero allocation (pre-allocated scratch). Engine reinitializes on sample rate change.

Spectrum config: `lower_cutoff_freq`, `higher_cutoff_freq`, `noise_reduction`, `auto_sensitivity` (fields + `MONSTERCAT_MIN_EFFECTIVE` in `data/src/types/visualizer_config.rs`; `src/visualizer_config.rs` re-exports everything). Smoothing filters (mutually exclusive, applied as `waves_filter` / `monstercat_filter` in `src/widgets/visualizer/state.rs`): `waves` (Catmull-Rom, `waves_smoothing` 2–16) or `monstercat` (exponential; values < `MONSTERCAT_MIN_EFFECTIVE = 0.7` are snapped to 0 / off; default 1.0).

## Module Structure

- `widgets/visualizer/mod.rs` — `Visualizer` Iced widget glue (its `view()` wraps a `ShaderVisualizer` in `iced::widget::shader`); `build_shader_params(...)` constructs the `ShaderParams` from a config snapshot, theme palette, and viewport
- `widgets/visualizer/state.rs` — `VisualizerState` runtime (audio callback, FFT pipeline, peak/effect state, display buffers); also `interpolate_bars`, `waves_filter` / `monstercat_filter`. `VisualizerTiming` is a zero-sized struct holding the per-frame tick constants (`TICK_RATE_HZ = 60`, `TICK_INTERVAL`, and an ms variant) all derived from one rate
- `widgets/visualizer/flash.rs` — `FlashField`, the Bars beat highlight (the per-bar `flash_intensities` that `bars.wgsl` blooms toward `peak_gradient_colors[0]`). Pure and lock-free, stepped once per FFT tick from `update_flash_effect`: per-bar rises → plateau-aware peak picking + non-maximum suppression (one event per transient, sub-bar center) → an event list (attack/release envelope, raised-cosine kernel, outward ripple, soft-max combine) re-rendered into the buffer every tick. Tunables live in its one `TUNING` block. Time advances per processed audio chunk, so it freezes while paused. The shader response is LINEAR in the buffer (`BARS_FLASH_GAIN`, weighted by height within each bar); squaring it collapses the spread onto the core bar
- `widgets/visualizer/particles.rs` — `ParticleSystem`, the CPU particle simulation for the Scope ring (curl-noise flow field, ambient + crest-spark spawns, audio/beat-scaled launch). Positions are normalized ring-space; snapshotted into `DisplayBuffers.particles` (two `vec4` per particle) for the GPU
- `widgets/visualizer/reflection.rs` — Reflection (Bars / Lines): `WATER_LINE` (the visualizer draws in the band above it), `REFLECTION_STRETCH`, and `KickRipples` (a ripple per beat onset under the bar that jumped hardest; `RIPPLE_SLOTS` events the shader ages). Stepped in `tick()` while the active mode's `reflection` is on
- `widgets/visualizer/horizon.rs` — Horizon (Bars / Lines): `HorizonRows`, the last `ROWS` spectra (one every `ROW_EVERY` ticks, newest first), `RowShape::Stepped` for Bars (one height per bar, grouped by max past `MAX_ROW_BARS`) or `Smooth` for Lines (Catmull-Rom); each row runs `MARGIN` past both edges with the spectrum mirrored outward. Snapshotted into `DisplayBuffers.horizon`, uploaded into the particle storage buffer (binding 4; Scope's dust never draws in the same mode)
- `widgets/visualizer/pipeline.rs` — `MAX_BARS = 2048`, `MAX_PARTICLES`, GPU buffers, per-mode + MSAA + particle/beam render pipelines, and the bloom/echo/crt post-process pipelines; `VisualizerPipeline::new` (the struct itself is declared in `shader.rs`). All pipelines are `TriangleList`
- `widgets/visualizer/shader.rs` — `ShaderParams` (the CPU grouping struct), the bytemuck-Pod GPU uniform `VisualizerConfig`, `ShaderVisualizer` (the `shader::Program` impl), render dispatch, MSAA texture cache, bloom/echo/crt post-process wiring, blit shader
- `widgets/visualizer/shaders/bars.wgsl`, `lines.wgsl`, `scope.wgsl` — the three mode shaders; each declares a `Config` struct that must mirror the GPU uniform `VisualizerConfig` (`shader.rs`, NOT `ShaderParams` — that is a CPU-side grouping struct with a different field list) verbatim; a drift is silent memory reinterpretation. `horizon.wgsl` binds the same uniform and carries the same block. Interlocks: const-asserts in `shader.rs` pin alignment (16), size (8336), and key offsets; `wgsl_config_field_names_match_rust_struct` in `mod.rs` pins the WGSL field names against the Rust struct, and `wgsl_config_blocks_declare_identical_fields` pins bars/lines/scope/horizon against each other. Update all five (shader.rs + the four shaders) together when changing a config field.
- `widgets/visualizer/shaders/bloom.wgsl`, `echo.wgsl`, `crt.wgsl`, `particles.wgsl`, `reflection.wgsl` — post-process + particle shaders with their own uniform structs (NOT pinned to `VisualizerConfig`). `bloom` = bright-pass → separable Gaussian blur → additive composite; `echo` = Milkdrop zoom/rotate feedback; `crt` = chromatic-aberration/scanline/vignette/grain/beat-punch composite (no screen curvature); `particles` = instanced additive glowing quads for the Scope dust field
- **WGSL compile gate:** `wgsl_compile_tests` in `mod.rs` parses + validates every shader `pipeline.rs` compiles (the seven files + the inline blit) through naga (`iced::wgpu::naga`, `Capabilities::empty()`), so a WGSL error fails `cargo test` instead of panicking at first paint. A new `create_shader_module` call needs its own `*_wgsl_compiles` test (a count check enforces it). The substring tests in `wgsl_helper_tests` stay: they pin helpers/consts a still-compiling shader could lose

**Render path:** non-MSAA fast path by default; switches to **4× MSAA → resolve → blit** when perspective lean is active (the `has_perspective` flag on `VisualizerPrimitive`, set from `bar_depth_3d > 0.001`, gates the path per-frame).

`VisualizationMode` enum (`data/src/types/player_settings/visualizer.rs`): `Off`, `Bars`, `Lines`, `Scope`, `Milkdrop` (cycled by the player-bar toggle and `v` in that order). The UI enum (`widgets/visualizer/mod.rs`) has `Bars`/`Lines`/`Scope`/`Milkdrop` (`from_setting()` maps the setting, `None` for Off). Mode categories are exhaustive predicates on it, never a `==` list: `fills_panel()` (Scope | Milkdrop, the over-cover panel), `is_stroke()` (Lines | Scope: SDF stroke, fixed point count, no CPU smoothing or flash field, bloom glow) and `uses_waveform()` (Scope: the time-domain waveform goes into `bar_data`). The shader primitive carries the enum (the uniform's `mode: u32` is informational; nothing reads it back). The FFT worker's mode is one `WorkerMode` cell in `VisualizerState`, written from update only by `Nokkvi::sync_visualizer_mode` (with the feed gate) on a mode change, a settings load, and when login builds the visualizer; the per-frame `.mode()` builder in `view()` never writes it.  `MIN_BAR_COUNT = 4`; bar width interpolates between `bar_width_min` and `bar_width_max` over a 400→2560px window range.

**Placement.** Bars and Lines each carry a `VisualizerPlacement` (`OverCover` default / `BottomBand`) — a per-mode field on `BarsConfig` / `LinesConfig`, same `wire_enum!` convention as the others. `BottomBand` draws a band above the player bar (every view); `OverCover` draws over the panel cover (Queue, Radios, Theater) whatever the play state (it freezes when paused) — the slot the Scope ring uses (Scope is always over-cover, with no placement of its own). Over the cover, Bars/Lines honor the `Visualizer Height` setting (`height_percent`) as a bottom-anchored fraction of the cover height; Scope fills the panel (its ring sizes off `scope.radius`). `widgets::visualizer::resolve_placement(mode, bars_placement, lines_placement) -> VisualizerSlots { bottom_band, over_art }` is the single source of truth for the render fork (the two slots are mutually exclusive); `app_view` calls it for the bottom band and in `Nokkvi::over_cover_overlays()`. The over-cover layer order (cover, lyrics scrim, visualizer, boat, lyric text; under MilkDrop the scrim sits above the visualizer) lives once in `compose_cover_panel` (`base_slot_list_layout.rs`), shared by the square and stretched panels, so a new layer goes there. The surfing boat rides the Lines wave in either placement — the bottom band (`app_view`) or over the cover (via `OverCoverBoat`).

## Bars Mode

Mode enums live in `data/src/types/visualizer_config.rs` as `wire_enum!` invocations (explicit per-variant wire literals tied to per-variant `#[serde(rename)]`, explicit `#[repr(u32)]` discriminants; the macro generates `ALL` / `as_wire_str` / `all_wire_strs` / `from_wire_str` (tolerant Default fallback) / `as_u32`; declaration order = settings-dropdown display order). The settings dropdowns derive their option lists from `all_wire_strs()` via each entry's `ui_meta.options`; enum dispatch parses with `from_wire_str` (visualizer dropdowns key on WIRE strings, unlike the `from_label` tabs). Pin tests assert each `ALL` carries every variant exactly once in declaration order. Enums:
- `BarsPeakMode`: `None` / `Fade` / `Fall` / `FallAccel` / `FallFade`. `peak_fall_speed` 1–20.
- `BarsGradientMode`: `Static` (0) / `Wave` (2) / `Drift` (3) / `Swell` (4) / `Pulse` (5) / `Ripple` (6). **Discriminant `1` is intentionally skipped** — `bars.wgsl` has no branch for it; the `bars_gradient_mode_never_emits_dead_1u` test in `data/src/types/visualizer_config.rs` pins this against accidental future use, and `bars_wgsl_branches_on_every_gradient_mode` (`widgets/visualizer/mod.rs`) fails when a variant has no `gradient_mode == Nu` branch. The four animated modes scroll/reshape the palette through `gradient_tri()` (a triangle wave, so there is no last->first seam) and are tuned by the `BARS_DRIFT_*` / `BARS_SWELL_*` / `BARS_PULSE_*` / `BARS_RIPPLE_*` constants; Pulse reads the CPU-side `average_energy`. (The old 3 Shimmer / 4 Energy / 5 Alternate were dropped in b92d311; their numbers were reused with new wire strings, so stale configs naming them still fall back to Wave.)
- `BarsGradientOrientation`: `Vertical` (within-bar) / `Horizontal` (bass → treble across bars).
- `BarsPeakGradientMode`: `Static` / `Cycle` / `Height` / `Match` (separate enum from bar gradients).

**LED gap.** In LED mode the gap between segments is `spacing_per_bar` (`bar_spacing` + `border_width` when borders are on), the same fill-to-fill distance bars have horizontally. It is computed by the `led_segment_gap()` helper in `bars.wgsl`, which `vs_main` also calls for the horizontal layout, so the two cannot drift. Each LED is its own outlined box: both the fill and the front and side border quads (vertex output `is_border`, `@location(10)`; top borders and peak fills carry 0) measure the gap with `led_gap_offset()`. `led_gap_cuts_border()` keeps this LED's top outline and the next LED's bottom outline, so the gap reads outline | background | outline when `bar_spacing > border_width` and the outlines merge otherwise. In 3D every LED is a cube, not just the topmost: only the topmost LED has top-face quads, so the front and side fills paint each lower LED's top face into the gap above it (`led_gap_shows_top_face()`, at `FACE_BRIGHTNESS_TOP`) and the border cut keeps the outline around it, both through `on_led_top_face()`, which tests the parallelogram `compute_top_fill`/`compute_top_border` draw, from `x_in_bar` (`@location(11)`) and the gap offset; the next LED's bottom outline hides the rest of the face, so a gap narrower than the depth shows only a sliver of it. The 3D side-face unslant is keyed on `face_type` (4 or 5), not brightness, so the side border quad unslants too.

## Reflection + Horizon (Bars / Lines)

Per-mode bools `reflection` / `horizon` on `BarsConfig` and `LinesConfig` (default off), routed through `ShaderParams` by `build_shader_params` like trails/echo (Scope and MilkDrop never get them).

- **Reflection** forces the offscreen path. `prepare` writes the uniform viewport height as `bounds.height * WATER_LINE` and the scene + echo ring-only passes set their GPU viewport to the same band (`scene_tex_h`), so bars / line / peaks / Horizon all lay out above the waterline untouched. The `reflection` pass (after the scene blit and the echo fresh-particle pass, before the bloom composite, so the glow spills over the surface) reads the DISPLAYED texture (resolve / trail / echo) and fills the band below: a dark body from the theme's border colour decoded to linear (the bar pipeline feeds raw sRGB to an sRGB target), the scene mirrored about the line and squashed by `REFLECTION_STRETCH`, perspective ripples (fine at the line, wide below; noise-driven, never a fixed pixel period, which chopped solid bars into LED-like blocks), a downward smear, a shimmering rim, sparse glints, and the `KickRipples` packets. The Lines boat rides the band: `boat_physics::LineGeometry { mirror, reflection }` feeds `wave_baseline_and_scale`.
- **Horizon** is drawn first in `draw_bars_and_lines` (one fullscreen triangle, `horizon_pipe`), behind the bars / line. Rows are composited FRONT TO BACK in the shader; returning the first row that covers a pixel leaked the cover through its anti-aliased edge as bright stripes. Bars rows are stepped (gaps, LED cuts, sitting on their own baseline, gradient bodies lost to mist); Lines rows are smooth (full fill and crest gated on relief). A quiet stretch must never drop out of a row, or the horizon goes empty wherever the music is low (usually the sides): it keeps a floor, a dim contour over a dark lip for Lines (`FLAT_*`) and a one-LED / `BAR_STUB_PX` stub per bar for Bars, light enough that the cover still shows. Bodies are dark/opaque enough to read over a bright cover: pure light glows vanish there (an aurora backdrop was tried and was invisible).

## Lines Mode

- `LinesStyle`: `Smooth` (Catmull-Rom spline) / `Angular` (straight segments).
- `LinesGradientMode`: `Breathing` / `Static` / `Position` / `Height` / `Gradient`. Reuses bar gradient palette.

6-instance render (`instance_index` in `lines.wgsl`): fill / outline / main × normal / mirror. Per-vertex coloring, optional fill / mirror.

**Stroke + glow (a7ab6efe).** The stroke is an analytic **SDF over miter-tiled per-segment quads** (`TriangleList`): adjacent quads meet on the join bisector so they tile with no overlap or gap, and coverage is `sd_segment(frag_pos, seg_a, seg_b)` — a true distance, so round joins/caps are free and the strip can never fold (the old fixed-width triangle-strip ribbon spiked at acute bends). The neon halo is NOT an in-shader analytic halo (those spike/facet at sharp tips) — the shader draws only the thin crisp core and the glow is the separable-blur **bloom post-process** (`bloom.wgsl`) re-purposed for the stroke (wider blur, near-zero brightness cutoff so the whole thin line glows evenly), driven by `glow_intensity` independently of the user's global Bloom toggle. Scope ports the identical stroke to its closed ring (wrapping via `ring_point`, raw asymmetric waveform preserved).

Key settings: `point_count` (8–512), `line_thickness`, `outline_thickness`, `fill_opacity`, `glow_intensity`, `mirror`, `style`, `boat` (toggle the surfing-boat overlay; `widgets/boat.rs`, CPU-only, themed via `embedded_svg::themed_boat_svg()` using `border_color`).

## Scope Mode

Circular oscilloscope: a time-domain waveform plotted as a closed ring over the panel cover (no placement of its own). `ScopeConfig` reuses `LinesGradientMode` / `LinesStyle` and the same SDF stroke + bloom-glow path, plus ring-only geometry. `tick()` snapshots the raw PCM chunk for the ring (`uses_waveform()`; asymmetric, untouched — design intent is waveform purity); the FFT still runs for the glow/beat/band effects.

Settings mirror `ScopeConfig` (`data/src/types/visualizer_config.rs`) + its `settings_tables/visualizer.rs` rows. Non-obvious defaults: `point_count` 16; `gradient_mode` `LinesGradientMode::Height` (052c19ea, reads better over cover art); `beam` (additive woscope-style ring) and `particles` default on; `echo` defaults to `1.0`.

## MilkDrop Mode

Plays MilkDrop presets (Butterchurn's pre-converted JSON) through `particle-milkdrop` + `particle-audio`, pinned to the fork `f-o-o-g-s/ojodrop` (branch `nokkvi-warp-alpha`: upstream 093e4098 + five patches: the custom-warp `WarpParams` UBO folded into group 1, `set_named_texture` with 512 px atlas cells, case-insensitive EEL identifiers, `sampler_prev_comp`, and the warp's `ret_alpha`). Over-cover only: it replaces the Queue/Radios cover and fills Theater Mode (`resolve_placement` → `over_art`). Module: `widgets/visualizer/milkdrop/` (`shared.rs` = `MilkdropShared`, `program.rs` = the `shader::Program`/`Primitive`/`Pipeline`, `transition.rs` = the pure crossfade bookkeeping (`SlotPair`, `Fade`, `BlendPattern`, `fade_frames`), `blit.wgsl`, `mod.rs` = size math, error scopes, `compile_preset`, `build_renderer`, the bundled table); app side in `update/milkdrop.rs` + `state/milkdrop.rs`; library in `data/src/services/milkdrop_presets.rs`.

- **Audio path (two threads).** `VisualizerState::tick()` in MilkDrop mode skips the spectrum engine and pushes the WHOLE buffered run (no three-chunk cap: the analyzer is stateful and a splice reads as a click/onset) into a `particle_audio::Analyzer`, rebuilt only when the stream rate changes (never on `pending_engine_reinit`, which every settings write sets). It publishes `Features` into `shared.features` with `try_lock` and the DECIMATED `analysis_sample_rate()` into `shared.analysis_rate`. The feature→engine mapping in `apply_features` is a straight field copy, matching the standalone player.
- **Render path.** The engine renders offscreen (`render_to_retained_comp`, never `render(view)`, which clears whatever it gets) into its retained `Rgba8Unorm` texture; `draw` blits that into iced's pass (viewport/scissor already set). `prepare` alone mutates the renderer: swap in a finished build (seeding its feedback from the renderer on screen via `seed_feedback_from`, as MilkDrop does: presets that grow from the previous picture stay black without it; it declines when sizes differ, and the first preset of a session starts black), debounce + `try_resize` (then render once, since the new texture starts black), advance at most once per `MILKDROP_FRAME_INTERVAL` (1/60 s catch-up schedule) only while `running`. Render size = panel px with the shorter side capped by Render Quality (`desired_render_size`).
- **Crossfade.** The pipeline holds a `SlotPair`: the incoming renderer and, during a fade, the outgoing one. An arrival over a drawn slot starts a fade of `shared.crossfade_frames` advances (read once per arrival); both sides advance in lockstep on the incoming's schedule, and progress counts advances, so pause freezes the mix. The seed picture comes from the dominant side (the outgoing below half progress); a third arrival mid-fade keeps that side and drops the other, so never more than two renderers live. Cover sync and resize reach both. The blit binds the incoming at group 0 and the outgoing at group 1 (a solo draw binds one twice with progress 1) and mixes per pixel with a random pattern (uniform staggered-max, wipe, radial, plasma) and a soft band in linear light; `prepare` writes the 32-byte params every frame from the same `blit_plan` `draw` follows. A lost outgoing ends the fade silently (never `slot_lost`); a lost incoming drops both and is blamed. `trim()` ends a fade when the panel has not drawn recently.
- **Off-thread builds with generations.** `milkdrop_load` bumps `generation` (mirrored to `shared.current_generation`) and parses + translates shaders in `spawn_blocking`; the renderer is built on a clone of iced's device (captured in `prepare`, epoch-tagged) under Validation + OutOfMemory error scopes (`run_in_error_scopes`; wgpu's default handler panics). A build hands its renderer over through `shared.built` (`offer_built` refuses a stale generation); only `Result<(), String>` rides the message. Five failures in a row (build errors or a renderer lost to a GPU error in `prepare`) stop auto-advance with one warning; `slot_lost` carries the lost renderer's generation, so a loss after a switch blames the OLD preset, not the build waiting to swap in; the count resets when the first frame is drawn (`shown_generation`), which is also when the name toasts.
- **Running** = MilkDrop mode ∧ playing ∧ ¬paused ∧ Home ∧ window open ∧ Queue/Radios/Theater ∧ the panel's `prepare` ran in the last 500 ms (`mounted_recently`; Artwork Column Never, a narrow window and split view draw no panel). Nothing advances, switches, builds or toasts otherwise; paused keeps the last frame.
- **Preset picker** (`update/milkdrop_picker.rs`). While `milkdrop.picker` is open it holds `locked = true` (the open lock state is restored on close), the tick calls `milkdrop_picker_sync_preview` instead of the timer / empty-slot advance (one build at a time: a list that moved on while a build was in flight catches up on the tick after it lands), `milkdrop_failed` does not advance to a random preset, name toasts are suppressed, and the `preset` IPC verb is refused. Previews never enter history; choosing pushes the preset from open. `chosen_generation` marks a chosen load until its first frame: if it fails, the lock is released so the random replacement is not held. Opening cancels a roulette spin. `milkdrop_release` discards the picker.
- **Release** is a generation watermark (`released_below`), enforced in `trim()` (every frame, mounted or not) and at the top of `prepare`: leaving the mode, stop, logout and closing the window drop everything older, both sides of a fade included. A one-shot flag would be consumed later and drop a newer load's renderer.
- **Pack + curation.** `assets/milkdrop/*.json` is embedded by `build.rs` (`BUNDLED_MILKDROP_PRESETS`); remove a dud by deleting its file. `~/.config/nokkvi/milkdrop/*.json` adds user presets (same stem shadows bundled), rescanned at login and on the refresh key in MilkDrop mode. Hidden + favorite presets live in `~/.config/nokkvi/milkdrop/curation.toml` (`curation.debug.toml` in debug builds); each hide logs `milkdrop: preset hidden` at info. The `bundled_pack_compiles` (naga) and `bundled_pack_builds_on_icedlike_limits` (needs a GPU) tests are `#[ignore]`d; run both when the pack or the engine pin changes.
- **nokkvi's own presets** (`assets/milkdrop/nokkvi - *.json`, generated by `scripts/gen-milkdrop-presets.py`; edit the script, not the JSON). Colours are `NOKKVI_*` placeholders filled by `palette::PresetPalette::substitute` right before parsing (`compile_preset` takes the palette): `NOKKVI_<ROLE>` → `vec3` in shaders, `NOKKVI_<ROLE>_R/_G/_B` → numbers in EEL, `NOKKVI_LIGHT` → 1/0; roles `BG SURFACE TEXT ACCENT HIGHLIGHT WARM RAMP0..RAMP5` (the ramp is the theme's visualizer gradient), always from the theme's DARK palette (accent, highlight and ramp come from the cover while Visualizer From Album Art is on): the presets are light-on-dark (additive glows, trails to black) and a light palette washes them out, so light mode shows a dark panel in the theme's dark colours. Text without the prefix is borrowed untouched. A themed preset reloads (same preset, no history push) when the palette really changes: `theme_generation()` also bumps on every settings reload, so the tick asks `PresetPalette::recolours` (colours, plus the light flag only for presets that read `NOKKVI_LIGHT`) before reloading. When only one preset is eligible, the timer, a track change and `n` keep it running instead of rebuilding it from black. The `nokkvi` Presets source draws only the `nokkvi - ` names.
- **The playing cover.** A preset samples it as `sampler_cover` / `sampler_fc_cover` / `sampler_fw_cover` (flip v: sample `(x, 1 - y)`). The tick decodes the playing cover (station logo on radio) off-thread to ≤512 px, padded square, once per artwork handle id (`cover_pending` / `cover_sent`), asks once for the album's large cover (only the Queue's centred row and Theater load it otherwise), publishes a neutral stand-in for a new owner with no art (never the previous album's), and publishes via `MilkdropShared::publish_cover`; `build_renderer` sets it before the warm-up frame and `prepare` swaps a newer `cover_version` into the live renderer in place (`set_named_texture`, under error scopes). The env-var texture folders (`MILKDROP_TEXTURE_PATH`) still work for other named images.
- **The COMP's own last frame.** A COMP that samples `sampler_prev_comp` (`textureLod(sampler2D(sampler_prev_comp, sampler_prev_comp_samp), uv, lod)`) reads the picture it drew one frame earlier: same `uv` = same pixel (no flip, unlike the cover), a full mip chain of true 2x2 averages (blur by LOD; the feedback's own mips are NOT averaged), alpha 0 until the first frame and after a resize. The engine aliases it onto the point-named sampler slot in the COMP only, so that COMP can use neither named textures (`sampler_cover`) nor `get_fft`/`get_wave` (the WARP still can); the WARP cannot use it. Costs ~0.5 ms at 1080p for the capture. The fjord uses it for its echo + depth of field (reprojected with last frame's camera, which its warp keeps in the data block).
- **The feedback's alpha.** A custom WARP may set `ret_alpha` (default `1.0`, so presets that never name it write an opaque alpha): the feedback keeps it as a fourth data channel that the next warp and the COMP read as `texture(sampler_main, uv).w`. Only warp output owns it; shapes, waves and borders drawn into the feedback blend over it, and the previous preset's seeded picture arrives with that preset's alpha (1 unless it set `ret_alpha` too), so wipe it on the first frames (`* step(2.5, frame)`). The blur textures write alpha 1, so they never carry it. The starfield nebula keeps its star trails there while the reaction owns RGB.
- **Debugging.** The engine reads `MILKDROP_DUMP_FIXED` / `MILKDROP_DUMP_GLSL` / `MILKDROP_DUMP_WARP_WGSL` (dump shader text to stderr) and `OJODROP_TEXTURE_PATH` / `MILKDROP_TEXTURE_PATH` (named-texture images) at runtime.
- **Settings** under `[visualizer.milkdrop]` (`MilkdropConfig`): `preset_interval_secs` (0-600, 0 = never), `switch_on_track_change`, `preset_source` (`all`/`favorites_only`/`nokkvi`), `render_quality` (`low`/`medium`/`high`/`native` → 480/720/1080/uncapped), `show_preset_names`, `preset_crossfade_secs` (0-10, default 2, 0 = cut; the tick stores `fade_frames(secs, interval)`, clamped to half the live interval, in `shared.crossfade_frames`). Read live each tick (`milkdrop_apply_config`).

## Configuration

- Behavior under `[visualizer]`, `[visualizer.bars]`, `[visualizer.lines]`, `[visualizer.scope]`, `[visualizer.milkdrop]` in `config.toml`
- Colors under `[dark.visualizer]` / `[light.visualizer]` in active theme file: `bar_gradient_colors`, `peak_gradient_colors`, `border_color`, `border_opacity`, `led_border_opacity`
- **Visualizer From Album Art** (`general.dynamic_visualizer`) swaps the bar and peak gradients for ones built from the playing cover (`theme/cover_visualizer.rs`) while it is on; read them through `theme::get_visualizer_colors()`, never the theme file's own set (`get_visualizer_colors_dark()`). Themed MilkDrop presets take the cover's accent, highlight and ramp through `theme::cover_milkdrop()` in `PresetPalette::from_theme`, so they recolour (the normal palette-change reload) on a track change only while that switch is on.

## Configuration pipeline

- Pure types (`VisualizerConfig` + Bars/Lines/Scope/Milkdrop + the `wire_enum!` enums + `validate()` + the `keys` module incl. `keys::ALL_KEYS`) live in `data/src/types/visualizer_config.rs`; the UI residue (`ThemeBarColors`, `SharedVisualizerConfig` + `apply`/`snapshot`, `ConfigWatcher`) stays in `src/visualizer_config.rs` with a glob re-export.
- Persistence is config.toml `[visualizer]` ONLY — never redb (`persisted_player_settings_json_has_no_visualizer_key` pins it). `SettingsManager` holds an in-memory `visualizer` field (startup phase 1 + `reload_from_toml` via `read_toml_visualizer`), mirrored wholesale onto `LivePlayerSettings.visualizer`.
- Dispatch + UI rows come from the `Tab::Visualizer` `define_settings!` table (`data/src/services/settings_tables/visualizer.rs`): setters mutate `mgr.with_visualizer(...)` (validate rides along); each entry's `ui_meta` builds its row (`build_visualizer_tab_settings_items` consumed by `items_visualizer.rs` via `MacroRows`). Several f32 config fields surface as INT pixel rows — `every_visualizer_macro_row_dispatches` pins row↔dispatch type agreement.
- Writes: `handle_settings_write_config` does the surgical per-key config.toml write (color sub-tables survive — never whole-section on this path), then routes through `apply_visualizer_settings` → `push_visualizer_to_shared` (change-gated) — deliberately NOT the startup-grade `PlayerSettingsLoaded` / `handle_player_settings_loaded`, which re-applies playback/SFX/engine/column state and would clobber an in-flight async persist (e.g. a just-released volume slider). monstercat↔waves exclusivity lives in the data-crate setters; `visualizer_secondary_writes()` (`update/settings.rs`) diffs before/after so the write covers BOTH keys to config.toml (pinned by `visualizer_secondary_writes_derive_from_setter_state`) — config.toml wins on reload.

## Runtime

- Hot-reload: config watcher → `SettingsConfigReloaded` → `reload_from_toml` (re-reads `[visualizer]`) → `PlayerSettingsLoaded` → shared config apply
- Dirty-flag gated redraws: `is_dirty()` / `clear_dirty()` — GPU idle when paused
- `apply_config()` sets `pending_engine_reinit` — FFT thread picks it up, prevents stutter
- Resize debouncing: 100ms for bar count changes
- The FFT tick takes the spectrum-engine, sample-buffer, display and peak locks with `try_lock()` and skips the tick on contention (CLAUDE.md)
