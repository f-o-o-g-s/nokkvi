# Common Gotchas

## Queue & Indices

- **Queue rows are addressed by `entry_id` (per-row `u64`), not indices, not `track_number`**: `track_number` is a 1-based queue-position label stamped at backend-projection time (`build_queue_song_ui_view_data` in `data/src/backend/queue.rs`). It drifts the moment the UI applies an optimistic local mutation, and stays stale until the backend re-projection arrives. Every UI write path against the queue carries `entry_id`(s) and bottoms out at: `play_entry_from_queue`, `move_queue_batch_by_entry_ids`, `remove_entries_by_ids`, `play_next_in_queue`. The Focus path mirrors: `FocusCurrentPlaying` / `FocusOnSong` carry `u64` and the handler does `position(|s| s.entry_id == eid)` — never compare `track_number`. `MoveItem` (single-row drag) carries `source_entry_id` snapshotted at pick time — a mid-drag viewport shift (playback auto-follow) or reload can't re-resolve it to a different row — plus a live drop index `to` (`to == len` appends past the last row); the handler captures the backend target as `MoveBatchTarget::AboveEntry`/`End` BEFORE the optimistic reorder shifts indices, then persists via `move_queue_batch_by_entry_ids`, same as `MoveBatch`.
- **`handle_queue` reads rows by borrow**: the slot indices it resolves are relative to the rows the view shows (filtered under a search). It keeps an owned list (`filtered_owned`) only when a search produced one and otherwise borrows `library.queue_songs` through the field path, which stays disjoint from `&mut self.queue_page`, so a message costs O(viewport). Derive `rows` where it is read (a `&mut self` call ends the borrow), and refresh `filtered_owned` in any arm that changes the search, the order, or (under a search) the rows. A new arm follows the same shape.
- **Batch reorders go through `move_block_before`** (`nokkvi_data::utils::reorder`): the queue's `MoveBatch` arm and the playlist editor's batch drop resolve their pick-time entry_ids to live positions in one `HashSet` pass, then move the block in one more (O(n + k), rows moved, never cloned; proptest-pinned against the old remove/insert loop). A new multi-row reorder calls it too. The backend's `move_batch_by_entry_ids` still runs its own remove/insert loop under the queue write guard.
- **Stale multi-selection across refreshes**: `handle_queue_loaded` and `apply_queue_sort` clear `selected_indices` + `anchor_index`. Without this, indices kept pointing at whatever rows occupied those positions after a consume-mode auto-advance / external refresh — different songs.
- **Three sources of truth for "what's playing"**: the queue play cursor (`current_order`, from which `current_index()` is derived), `QueueNavigator.current_song_id`, and the engine's active source. The remove path uses `decide_removal_aftermath` (pure) → `PlaybackController::apply_removal_aftermath` to keep all three in sync; never bypass it, with the one exception below. History append is intentionally skipped on remove (the song was deleted, not skipped past). The decision's `RemovalTransport` classifies the engine through `RemovalTransport::from_engine`, which takes the UI's active station URL (`remove_queue_entries` is passed `ActivePlayback::radio_station()`'s `stream_url`; the engine's own `stream_is_infinite` lags a station start) AND the engine's live source: a station owns the engine only while the engine's source IS its stream, because `ActivePlayback::Radio` is cleared only by `guard_play_action` and so outlives the stream whenever a cold-start Play or a dropped station moves playback into the queue. Under `StreamingRadio` the plan is always `RetargetNavigator`, which points the navigator at the cursor's song and leaves the engine's source and transport untouched, so removing the navigator's row can no longer swap a queue song in under the station's name and emptying the queue can no longer stop the stream. `AppService::clear_queue` still stops the engine unconditionally, so Shift+D under a station is NOT covered.
- **Remove Duplicates is decided in the backend, from the live cursor**: `AppService::remove_queue_duplicates` → `QueueManager::remove_duplicates` picks the rows under the queue lock (rule: `nokkvi_data::utils::dedupe::duplicate_entry_ids`) and keeps the cursor row as its song's copy, so playback never follows the queue and the path skips `decide_removal_aftermath` (that plan keys on the navigator's song, which can differ from the cursor's and would stop a station or reload the engine); it only resets the gapless prep. The UI mirrors the dropped entry_ids on `QueueLoaderMessage::DuplicatesRemoved` rather than guessing: `last_queue_current_entry_id` lags a track change. Every batch removal bottoms out at `remove_entries_by_ids`: one pass, one save.
- **`current_index` is a derived accessor, not a field**: `Queue::current_index()` computes `order[current_order]`. Write paths move the CURSOR (`set_cursor_to_row`, `rebuild_order_and_set_cursor`, or an order-slot `current_order` write); adding a parallel physical-index field back would reintroduce the desync bug class the 2026-07 redesign removed.
- **Progressive queue generation**: `ProgressiveQueueAppendPage` chains check `progressive_queue_generation` before appending — stale chains silently stop.
- **Play button cold-start**: resolves the selected row via `get_center_item_index` and plays its `entry_id` via `play_entry_from_queue` — not `queue_songs.first()`, not `track_number - 1`.
- **Gapless re-peek on mutation**: a queue mutation between gapless prep and `on_track_finished` calls `clear_queued()`. The transition path always re-peeks — `peek_next_song()` re-computes `queued` when it was cleared, then `PeekedQueue::transition()` consumes it — so the mutation can't strand the transition.
- **Queue sort label is demote-only**: `apply_queue_sort` is the SOLE promoter of the sort dropdown's applied state; `revalidate_queue_sorted()` (on `Nokkvi`) re-verifies the live order against the applied mode and only demotes to the grayed "Unsorted" placeholder. It runs from `handle_queue_loaded` and after every in-place reorder (drag, batch drag, Shift+arrow move) — any new in-place queue mutation must call it or the dropdown lies about the order.

## Multi-Selection & Batch

- **Ctrl+click toggle**: deselecting the last item must clear `selected_offset` to remove the center-highlight from the deselected slot.
- **Shift+click range**: clears existing selection first, then adds the range from `anchor_index` to clicked offset.
- **Context menu batch**: `evaluate_context_menu()` checks if the clicked index is in the selection; if not, resets selection to just that item.
- **Always `clear_multi_selection()` after batch ops** — prevents stale selections.
- **Settle the slot list when rows leave it**: `SlotListPageState::settle_after_shrink(shown_len)` drops the selection, its anchor and the click-to-focus marker (positions into shifted rows) and clamps the viewport. A kept marker snaps the next scroll back to it, past the end, where every slot renders empty. The queue's removals (`drop_queue_rows`) and the editor's go through it.
- **Cross-pane drag batch**: `cross_pane_drag.selection_count` (on the `CrossPaneDragUi` cluster) is snapshotted at press time; decoupled from subsequent selection changes.
- **Keyboard scroll clears selection**: `handle_navigate_up/down` clears `selected_offset` to prevent stale highlights.
- **Search clears the whole selection**: `handle_search_query_changed` (every slot-list view's search, Harbour's mirror included) drops indices + anchor + focus marker, because indices are relative to the filtered list and a non-empty set suppresses the center ring. A kept click left the filtered rows with no highlight.
- **So does every other reorder or buffer replace**: `clear_selection_for_refresh()` (all three fields), never `set_offset` alone (focus marker only) or `clear_multi_selection` alone (keeps the marker). The sites are `sort_radio_stations` (`src/main.rs`, on a real reverse or a count change — its `(ascending, len)` short-circuit keeps it off no-op calls) and BOTH branches of `apply_viewport_on_load` (`src/update/loader_target.rs`): the foreground branch clears too, because `get_effective_center_index` prefers the marker, so a sort change left Enter / Shift+Q acting on an off-screen row. The clear is safe for find-and-expand: `handle_loaded_with` runs `apply_viewport_on_load` BEFORE `try_resolve_pending_expand`, so the chain's `pin_selected` lands after it (pinned by `albums_foreground_reload_still_pins_a_pending_find_and_expand`). Genres and Playlists override `apply_viewport_on_load` and need no clear — their post-load `SetOffset(0)` click replaces the selection.

## Optimistic UI & Race Conditions

- **Tick handler race**: 10 Hz tick can overwrite optimistic state with stale backend state — use pending flags to prevent reversion before API response.
- **Source generation counter**: typed `SourceGeneration` wrapper (over `AtomicU64`) — every user-driven source change goes through `bump_for_user_action()`; renderer snapshots `current()` before releasing the engine lock and discards the callback if it changed. Prevents consume+shuffle replaying the just-consumed track.
- **PagedBuffer pagination guard**: call `set_loading(true)` before dispatching a page fetch — prevents duplicate fetches on rapid scroll. `Nokkvi::load_paged` (`update/loader_target.rs`) owns this invariant plus the `needs_fetch` gate for paged views; `PaginatedFetch::from_common()` only bundles the request params.
- **PagedBuffer generation**: `generation()` bumps on every mutation. Use `(query, generation)` keys when memoizing filtered results.
- **One seek in flight, the rest merged**: every seek producer (slider, capsule, MPRIS, Previous's rewind, the IPC verb, the seek keys) goes through `Nokkvi::dispatch_seek` → `SeekState` (`src/state/seek.rs`). A relative onto a relative adds, an absolute replaces, a relative shifts a queued absolute. The relative arithmetic lives in `PlaybackController::seek_relative` under ONE engine-lock acquisition — the UI's whole-second `playback.position` freezes while a seek holds that lock, so `position + delta` would land a burst of repeats as a single jump.
- **The seek epoch drops a pre-seek tick**: `PlaybackStateUpdate.seek_epoch` is captured synchronously in `handle_tick` and gates exactly THREE position-derived effects in `handle_playback_state_updated` — the clock write, `track_listening_time`, and the MPRIS position push. Do NOT widen it to the whole update: a held seek key bumps the epoch ~25x/s against 10 Hz ticks, so the title, duration, gapless prep and queue highlight would freeze on the old track for as long as the key is held. `SeekApplied` carries its dispatch epoch too, so a result from a session cleared mid-flight is dropped rather than clearing a live seek's in-flight flag.
- **No listening credit while a seek is in flight**: `track_listening_time` resyncs `last_position` and credits nothing. A relative seek cannot write its target ahead of time the way `handle_seek` does, and a tick can land between the engine finishing a seek and `SeekApplied` arriving.
- **Artwork LRU caches go through `SnapshottedLru<K, V>`**: every artwork LRU on `ArtworkState` (`src/state/artwork.rs`, incl. the `{mini, collage}` pair on each `CollageArtworkCache`) is a `SnapshottedLru` newtype that maintains the view-borrowable `HashMap` snapshot automatically. Never pair a bare `lru::LruCache` with a manual `HashMap` snapshot — a fresh cache must use `SnapshottedLru`.

## Widget Tree & Focus

- **Widget tree stability**: changing the root widget type (Row→Column) destroys `text_input` focus. Use `base_slot_list_empty_state` for consistent structure.
- **Search input ID collisions**: each view needs a unique search input ID constant.
- **HoverOverlay canonical pattern**: `mouse_area(HoverOverlay::new(container(content))).on_press(msg)`. Wrapping a native button works in some places (press events are tracked passively — never captured — and `update` issues `request_redraw`), but reach for the canonical container pattern first.
- **`Length::Fill` stripe in unconstrained Row**: `container(Space).height(Fill)` in a row without explicit height expands to fill column space. Set `height(Shrink)` on the wrapper row.
- **Single-active overlay menu**: hamburger / kebab / checkbox-dropdown / context menus must NOT own local `is_open` state. Bubble `Message::SetOpenMenu(Some(OpenMenu::…))` to root — opening a new one atomically replaces the previous one.

## Audio Engine

- **Crossfade duration clamping**: `arm_crossfade()` clamps to `min(xfade, shorter / 2)`, rejects unknown (zero) durations, and skips songs shorter than the configurable `crossfade_min_track_ms` floor (default 10 s; `0` = blend everything with a known duration), pushed from settings via `set_crossfade_min_track_secs()`. The old fixed `MIN_CROSSFADE_TRACK_MS` constant is gone.
- **Bit-perfect gates the crossfade**: `arm_crossfade()` returns early when `crossfade_blocked(current_format, incoming_format)` — Strict hard-cuts every transition; Relaxed hard-cuts only on a cross-format change. The engine's EOF-fallback transition gates on the SAME `(current, incoming)` pair, so neither trigger can start a blend the other refuses and orphan the incoming stream.
- **Stale gapless prep on mode toggles**: mode toggle handlers call `reset_next_track()` to clear the prepared decoder, disarm the crossfade trigger, and cancel an in-flight AUTO blend. A live manual-skip blend is spared: its incoming is the track the queue already names, and cancelling it would strand the engine on the old track. `set_bit_perfect()` shares this contract — on a REAL mode change (the renderer reports the flip) it calls `reset_next_track()` too, because bit-perfect flips crossfade eligibility and an armed transition could otherwise desync. It's a no-op when unchanged so a routine settings save can't disturb an in-flight transition.
- **Track-completion lock**: the navigator releases its lock across engine I/O during track completion — do not re-introduce a held lock.
- **ReplayGain stash**: prefer `engine.load_track_with_rg(url, rg, expected_duration_ms)` — the atomic pair that calls `set_source(url, expected_duration_ms)` and then stashes ReplayGain on the renderer, so a load can't be interleaved. The stash comes second because `set_source`'s teardown can promote a live skip blend, which restages the promoted track's tags. Use `set_pending_crossfade_replay_gain()` for the crossfade decoder before its stream is built.
- **Repeat track replay**: `on_track_finished` natively supports repeat-track by re-loading the same row — it returns `TrackTransitionPlan::LoadFresh` (reload from the stream URL) or `PlayPrepared` (the gapless-prepared decoder), not a seek-to-start. Manual skip (next/prev) bypasses repeat-track (`get_next_song` in `services/queue/navigation.rs`).
- **Pulled server queue must be re-cued**: a `pull_queue` (savePlayQueue / indexBasedQueue) replaces the model via `set_queue`, which only mutates the queue — the engine keeps playing the pre-pull song unless `PlaybackController::cue_pulled_queue` re-cues it. Mid-song resume rides a one-shot engine `pending_start_ms` (consumed in `play()`'s fresh-start branch, cleared by `set_source` so a stale arm can't fire on a later reload). It must NOT route through `plan_click_play` — a skip-fade would blend the pulled song in from position 0, and the saved position could only land afterwards as an audible jump. (see audio-engine.md)

## Config & Persistence

- **Typed config writer routing**: `ConfigKey::AppScalar` → `config.toml`; `ConfigKey::Theme` / `ThemeArrayEntry` → active theme file. Match on the variant — never sniff key prefixes.
- **Config reload suppression**: the file watcher suppresses its own reflections via an identity-based registry — `record_internal_write()` stamps each write's `(path, content-hash)` and `was_internal_write()` (`data/src/utils/paths.rs`) matches it within a monotonic 500ms window — so a GUI-initiated write never echoes back through the watcher; the handler must apply its own change in-process. Theme writes call `theme::reload_theme()` right after the write; `visualizer.*` keys are dispatch-first (mutate the in-memory config, persist only on success — see `visualizer.md`).
- **Font is global, not per-theme**: `font_family` lives in `LivePlayerSettings` / `TomlSettings` and routes to `config.toml`. EQ modal `pick_list` must explicitly receive the active app font.
- **Database lock on re-login**: redb holds an exclusive lock; cache `StateStorage` on `Nokkvi.cached_storage` and reuse via `AppService::new_with_storage()`. Stop the engine + `TaskManager` on logout.

## Assets & Icons

- **Auto-generated SVG lookup**: BOTH icon namespaces — `assets/icons/*.svg` (Lucide, the paths every view references) and `assets/icons-phosphor/*.svg` (the alternate set) — are enumerated at build time by `build.rs`, generating `OUT_DIR/embedded_svg_generated.rs` (one `lookup()` keyed by full path + `KNOWN_PATHS`). Adding/removing an icon is just dropping the file in either dir.
- **Selectable icon set remaps in `get_svg`** (`src/embedded_svg.rs`): when the active set is Phosphor (the **default**), `get_svg(path)` first runs `phosphor_path()` (binary-searches the sorted `NAME_MAP` Lucide-stem → Phosphor-file table) and returns the mapped Phosphor bytes. A mapped-but-MISSING Phosphor file falls through **gracefully to the Lucide content** (not the play.svg fallback). The Lucide set skips the remap entirely. Only a genuinely **unknown** path hits the silent `play.svg` fallback (with a warn log). The filled transport/rating glyphs (`play`, `pause`, `skip-back`, `skip-forward`, `heart-filled`, `star-filled`) deliberately map to the Phosphor **Fill** weight; the rest use Regular.
- **`cargo test --bin nokkvi -- embedded_svg`** runs the guard suite: `all_svg_paths_in_source_are_registered` catches typo'd path strings; `generated_paths_match_assets_dir` re-confirms codegen saw both dirs; the `icon_name_map_*` tests pin the `NAME_MAP` (sorted, covers every Lucide icon, every Phosphor target ships, Fill weight for the filled glyphs); `get_svg_honors_active_icon_set` pins the remap end-to-end.

## Artwork

- **No persistent album-art cache**: every album/artist artwork fetch goes straight to Navidrome via `AlbumsService::fetch_album_artwork(...)`. Session-scoped Handle reuse comes from the UI's `album_art` (mini — sized generously because a 2×2 quad row claims up to 4 ids) and `large_artwork` maps in `ArtworkState` (capacities are consts in `src/state/artwork.rs`). The ONE persistent store is `RadioArtStore` (`data/src/services/radio_art_store.rs`): logo-less radio stations' remembered now-playing (ICY) art, a single bincode blob in the shared redb — bounded by entry count AND total bytes, LRU by fetch recency, server-URL-namespaced. Stations with an uploaded `coverArt` logo re-fetch via `getCoverArt` each session and are never persisted.
- **Version-aware refetch + negative cache**: the prefetch gates run through `should_refetch(cached_ids, versions, failed, id, version)`. The version is `artwork_version(&image, updated_at)` (`data/src/types/image_info.rs`): the entity's `imageHash` when a Navidrome 0.64+ server sends a valid one, else `updated_at` as on older servers. `build_cover_art_url_with_timestamp` puts a hash on the id (`al-<id>_<hash>`, no `_u=`) and a timestamp in `_u=`, so an old server's URLs and versions stay byte-identical. `ArtworkState.album_art_versions` (album-id → the version that warmed each slot) lets album-coherent surfaces (Albums view, Artists/Genres expansion and Harbour shelves via `album_prefetch_entry`, the Artists view's `ar-` minis) re-fetch when the server cover changes; with a hash that is exactly when the image bytes change, never on a play-count bump. Art the server marks `imageAbsent` is never requested by a surface that holds the entity (the album projection builds no URL; artist, large-art and Refresh paths check `album_image_absent` / `artist_image_absent`), and nothing is negative-cached for it, so a reload that clears the flag fetches normally. Passive surfaces (queue, song-mini, similar, playlist editor) carry only a per-song `updated_at` that would oscillate the album-id-keyed map, so they feed a constant `None` via `passive_artwork_version()` (id-only dedup). `ArtworkState.failed_art` is the negative cache: album/artist ids whose 80px fetch returned NO image (code-70 "Artwork not found" — an album that merely lacks a cover gets a placeholder *image* and caches normally, so it never lands here). Membership stops re-queuing a known-dead id on every scroll/resize/view-switch; a CHANGED `updated_at` bypasses the entry and re-attempts. Both maps are unbounded but reset wholesale by `ArtworkState::default()` on logout, so server-A failures never suppress server-B art.
- **MPRIS art is always present for a current item**: while a song or station is current and the cache dir is writable, `resolve_art_for_mpris` (`services/mpris_art_writer.rs`) always publishes `mpris:artUrl`, falling back to the app-icon placeholder, because shells keep the previous image when the key is absent. A failed cover or placeholder is retried after `RETRY_FAILED_AFTER` (60 s), never per tick: a station's logo token never changes while it plays, so no track change would retry it. Cover ids and station logos go through the writer as `file://` cache paths, so no credentialed `getCoverArt` URL reaches D-Bus. ICY `StreamUrl`s are published raw and only when http(s). The tick awaits this art before every state update, so it only fetches from the user's own server, never from a station's image host.
- **Always `Handle::from_bytes`**: `from_bytes` allocates a fresh `Id::Unique` per call — safe **only** because Handles are stored in the LRUs and reused across renders. Never re-create from bytes per frame; that bypasses Iced's GPU texture cache (`reference-iced/wgpu/src/image/raster.rs:55`).
- **Snapshot mirrors**: `view()` borrows the `HashMap` snapshot inside each `SnapshottedLru`, not the LRU directly, because LRU `get` is `&mut`. The newtype keeps both in sync on every `put` / `get_touch` promotion; no caller-side discipline needed.
- **Quad fetches gate on `album_art_pending`**: the 2×2 quad prefetch is re-dispatched from every scroll step and collage event, so each ×4 quad path filters against `ArtworkState.album_art_pending` AND inserts its queued ids (`quad_prefetch_tasks` / `strip_quad_prefetch_tasks` in `src/update/collage.rs`); `handle_artwork_loaded` releases the slot on success and failure alike so a throttled tile can retry. The expansion album fan-out (`expansion_album_artwork_tasks`) also filters on the set — genre expansion children lead with the same albums their row quad is warming, and `FocusAndExpand` fires both in one event cluster. Single-id prefetch surfaces stay gate-free; any new ×4 quad path must both consult and insert.
- **Frozen strip quad identity**: the queue strip's playlist quad renders from `strip_quad_album_ids`, snapshotted via `snapshot_strip_quad_ids()` on the FIRST queue load for the active playlist context (`handle_queue_loaded`) — at that moment queue order == playlist track order. Later queue reloads (consume advance, sort, SSE) intentionally leave the frozen ids untouched so prefetch and render agree on identity; `clear_active_playlist()` drops the snapshot with the context so the next playlist re-freezes from its own queue head.
- **SSE refreshes covers only through the reload**: a `LibraryChanged` event (wildcard or id-anchored) reloads the slot lists and triggers no artwork refresh of its own; a blanket re-fetch would re-download every cached cover. The post-load viewport prefetch then refetches only rows whose version changed, which with Navidrome 0.64 image hashes is exactly the changed covers, and `handle_artwork_loaded` drops the stale large art when a mini arrives at the rows' current hash while `ArtworkState.large_artwork_hashes` says the large art was requested at a different one. That map is separate from `album_art_versions` because the passive surfaces write `None` there, and the current-row check keeps a surface refetching an old hash from dropping the right image. Older servers send no hashes, so it never fires there.
- **Random-sort SSE protection**: background SSE reload mustn't corrupt the artwork ref when the active sort is Random — guarded in `library_refresh.rs`.
- **A one-off random draw must never use `_sort=random`**: Navidrome re-seeds its per-`(table, user)` seeded-random ordering for every query it maps to `Sort: "random"` arriving at `Offset == 0` (`resetSeededRandom`, `persistence/sql_base_repository.go`) — so a background draw silently re-permutes an in-progress Albums/Songs **Random**-sort pagination in the browse views (already-scrolled rows reappear, others are skipped). Passing an explicit `seed` does not help; that branch calls `SetSeed` on the same shared key, and the Subsonic `getAlbumList{,2}&type=random` endpoints route through the identical path. The two safe draws: **songs** → Subsonic `getRandomSongs` (`services/api/random.rs`; `ORDER BY random()` over rowids, touches no shared seed), **albums/artists** → `pagination::draw_random_row` (count-probe + random offset over the stable `RANDOM_DRAW_SORT`). Genres/playlists shuffle client-side, so their `"random"` is a no-op on the wire. Invisible to CI and to a single-view smoke test — it only shows up when one view paginates Random while another draws.
- **Genre identity — name vs tag id**: a server genre's `Genre::id` (from `/api/genre`) is a **tag id** (a hash of the lowercased value), NOT the name. Each wire key takes exactly one of the two. **`genre_id` carries the tag id**: on `/api/album` and `/api/song` it is an indexed `tag_id = ?` join since Navidrome 0.64 (`genreFilter` in `persistence/sql_tags.go`), so a name there returns HTTP 200 with zero rows and no error. `LibraryFilter::GenreId` pushes its `id`, `GenreUIViewData::songs_filter()` builds the Songs-view filter, and `load_genre_albums{,_full}` take the id. **The bare `genre=<name>` key on `/api/song`** (`load_songs_by_genre`, still a `json_tree` match on the tag value) and **Subsonic `getRandomSongs?genre=`** carry the name. Everywhere else the client identity is the **NAME**: `BatchItem::Genre` / `SongSource::Genre` / `PlayTarget::GenreRandom` / Harbour's fan-out results and collage/side-map keys. Harbour's quad fan-out takes `(name, tag id)` pairs, requests by id and keys the reply by name. Its Most Played genres are tallied from song `genre` strings, so `stamp_tally_genre_ids` stamps their tag id from the `/api/genre` list (exact name, then a lowercased match); a miss keeps `id == name` and that quad stays blank on 0.64+. The one id-keyed cache is the Genres view's collage pipeline (`handle_load_genre_collage` → `LoadCollage` → cache + `library.genres` row match), which is self-consistent end-to-end — keep it whole or convert it whole, never mix keys within a surface. Related caveat: Subsonic `getRandomSongs?genre=` matches via SQL `LIKE`, so a name containing `%`/`_` over-matches and matching is case-insensitive for ASCII letters only (SQLite's default `LIKE` does not case-fold non-ASCII, and Navidrome registers no ICU/custom LIKE) — never case-normalize a genre name client-side; send the server-canonical name verbatim. `getRandomSongs` / `getSimilarSongs2` / `getTopSongs` return Subsonic `Child` objects, which have **no `compilation` field** (only albums expose `isCompilation`) and spell the album artist `displayAlbumArtist` (aliased onto `Song::album_artist`, which is what keeps the crossfade album-continuity policy's Various-Artists escape alive). Any policy reading `Song.compilation` degrades silently on those paths — check `crossfade_policy.rs` before adding one.
- **Albums viewport clamp**: clamp `viewport_offset` against the new total count on background refresh — otherwise the viewport can land past the end after a remove.
- **A plain lyric sheet's stamps are all `time_ms == 0`**: drive it through `drift_center` (playback progress × `n - 1`, plus the wheel's `drift_offset`, clamped), and keep it away from `active_line_at`, whose `partition_point` every zero stamp passes — it would name the LAST line from the first tick and highlight it for the whole track. `active_index` stays `None` for a plain sheet's whole life; the guard lives at the apply path, at the tick, and once more where the column is drawn. Write the wheel offset already clamped, via `drift_offset_for` (the exact inverse of `drift_center`), so nothing banks hidden overshoot and a notch lands where it asked even in the final second, where the tick's whole-second duration puts progress above 1.0.
- **Lyrics overlay identity**: the lyrics + blurred-cover layer must gate on the **transport** (`playing || paused`), never on `current_song_id` / `is_queue()` — both survive `stop()` and are seeded from the restored queue at login, so gating on them scrims a bare cover with no audio. The backdrop must key on the **shown/resolved cover handle**, not the playing track: during the cold-art window the panel falls back to the centered row's cover, so rendering the playing track's lyrics over a *different* album is wrong.

## Misc

- **MPRIS multi-instance bus name**: nokkvi suffixes its bus name with `instance{pid}` (per the MPRIS spec) so two running instances don't silently fight over `org.mpris.MediaPlayer2.nokkvi` — without the suffix the loser of the race ends up with no MPRIS at all and nothing logs it. Don't drop the suffix.
- **Bringing the window back goes through `Nokkvi::show_window`** (`update/tray.rs`), the one entry point for the `show` IPC verb, a bare second launch, MPRIS `Raise` and the tray click's reopen half. It checks `main_window_id` FIRST: `set_window_hidden(false)` opens a window unconditionally, so reaching it with a live window (or in the boot gap before the first `WindowOpened`) leaves two. A live window can only be flagged: `window::gain_focus` is a no-op on Wayland (winit's `focus_window()` is empty), so the already-open path is `window::request_user_attention(id, Some(UserAttention::Informational))`, which the compositor shows as an urgency hint without stealing focus.
- **A service on its own thread must end with its subscription**, not only when its command channel closes: the app keeps the `*Connection` handle it got from `Connected` after the feature is switched off, so that channel never closes. The tray thread checks its event sender's `is_closed()` in `pump_commands` (`services/tray.rs`); without it, turning Show Tray Icon off left a dead icon behind. Services that run inside the subscription future (notifications) are torn down with it and need nothing.
- **Global hotkeys are suppressed on the login screen**: `handle_raw_key_event` early-returns when `screen == Screen::Login`. The login form owns its own keyboard (Tab focus + Enter on_submit); without the guard the always-on keyboard subscription double-dispatches — Tab is whitelisted past the capture guard and resolves to `SlotList(NavigateDown)` against the off-screen queue (firing the Tab SFX twice, churning hidden selection), and bare `x`/`c` toggle random/consume against an idle engine. Leave the `event::listen_with` subscription intact (reverting it reintroduces the swallowed Escape/Enter regression).
- **Bare modifier/lock keydowns are dropped**: `handle_raw_key_event` drops bare Shift/Ctrl/Alt/Super/CapsLock keydowns AFTER the hotkey-capture forward and BEFORE dispatch. They resolve to no hotkey, but otherwise a bare Shift arrives `Status::Ignored` and trips the smart-playlist rules editor's Editing-mode focus-loss grammar — committing + blurring the cell so the following typed capital leaks to a global hotkey (Shift+S = FindSimilar, Shift+D = ClearQueue). Placement after the capture forward is load-bearing so chord rebinding still sees the modifiers.
- **Shared key combos resolve deterministically**: `HotkeyConfig::lookup` and `find_conflict` share one `resolve` — a RESERVED action, then a configurable action whose binding differs from its default (the user put it there), then declaration order. Never iterate the `bindings` HashMap to pick a winner.
- **A shared key combo is surfaced, and capture can repair it**: `HotkeyConfig::shadowed_by(action)` names the action `resolve` hands this action's own binding to, when that is someone else — the producer for "this row shows a key it never gets". It drives the Settings row's subtitle (`items_hotkeys::hotkey_subtitle`, which leads with "Does nothing right now: …"); the badge's designed disabled state is still unrendered and would read the same accessor. `HotkeyConfig::plan_capture(action, combo)` owns the capture decision — `Write`, `Swap` (today's trade, when the action is on a DIFFERENT key), `Evict { from, to }` (already sharing: the other action goes home to its own default, only when that default is free and is not the contested combo), `Blocked { by }` (nothing is written). Every writing plan moves at most ONE other action, so it requires exactly one other claimant — with two or more the capture is `Blocked`, or the key would just go to a third action — and no plan ever moves a RESERVED action (`resolve` scans RESERVED first, so a hand-edited `escape = "F5"` really can surface as the claimant, and there is no Settings row to undo a move from). The view maps the plan and its badge text describes what was actually written; `Blocked` re-arms `capturing_hotkey` on purpose, because `render_hotkey_badge` draws `conflict_label` only while the row is capturing. Never re-derive the decision in the view — a bare "conflict? swap" wrote the other action back onto the same key when `old_combo == combo`.
- **Moving a hotkey default means adding a `RETIRED_DEFAULTS` row** (`data/src/types/hotkey_config/config.rs`) in the same commit. `normalize` then moves an action still sitting on its retired default to the new one — but only when the retired combo is contested AND the new default is free, so it can never strand an action on a key another binding already wins. Startup rewrites `[hotkeys]` once when it changed something; the hot-reload path never writes (config-watcher feedback loop).
- **Expansion sort state**: when expansion is active, sort/search may target the expansion. Check `expansion.is_expanded()`. Shift+Enter on Artists/Genres collapses the outer expansion.
- **Pending find-and-expand chain**: at most one `Nokkvi.pending_expand.target` (on the `PendingExpandState` cluster) runs at a time. Starting a new chain (or any user-driven view change matching `PendingExpand::host_view()`) supersedes the previous one. `PendingTopPin` re-pins the highlight after `set_children` lands.
- **Expansion artwork retry**: artwork fetches dispatched from inline expansions retry on transient failure and reject empty-bytes responses, so a flaky first request doesn't leave a permanent empty cell.
- **Chrome height**: a new bar stacked above a slot list is added inside that page's chrome function (`SlotListChrome::height`, `queue_chrome_height`, or `editor_chrome_height`), and a new input to it is derived once on `Nokkvi` (`library_page_chrome` / `queue_chrome_inputs`) and carried in the view data. That shared function is what keeps the stored `slot_count` equal to the rendered one, which keeps the drag mappers, find-and-expand, and the scrollbar thumb in step. A term counted in the render alone let the queue drag grab the row above the cursor (two above near the end) and pinned a found album one row above the viewport. Update constants in `widgets/slot_list.rs` when chrome changes.
- **Cross-pane drag center index**: snapshotted on drag activation (5 px threshold) — decoupled from subsequent state changes.
- **Mode-gated mini-player artwork**: `Nokkvi::mini_player_artwork()` returns `None` when `TrackInfoDisplay != MiniPlayer` — every other strip mode hides the mini-player section, so resolving the cached handle would be wasted work. Tests pin the gate in `update/tests/redesign_chrome.rs`.
