# Audio Engine

## Architecture

```
CustomAudioEngine
├── AudioDecoder (Symphonia)
│   ├── Standard: HTTP via RangeHttpReader (256KB chunks, MAX_CACHED_CHUNKS=16, prefetch on seek + background sliding-window read-ahead)
│   ├── Unsized:  a queue song the server sends with no length (its live transcode): one GET through AsyncNetworkBuffer, finite (EOF ends the track); seeks only by reopening at `timeOffset` (see "Seek by offset")
│   └── Radio:    HTTP via AsyncNetworkBuffer (tokio async → bounded mpsc → sync Read), generation-gated auto-reconnect (`radio_reconnect_loop()` → a `RadioReconnectOutcome` token; the caller owns the loop's `continue`/`break`) and a jitter prebuffer (`radio_jitter_prebuffer_step()`)
├── AudioRenderer → RodioOutput (shared rodio Mixer) → ActiveStream per track (signal chain: CLAUDE.md)
├── CrossfadeCoordinator (engine, `engine.rs`) — the engine-side crossfade cluster: `CrossfadePhase`, config and setting mirrors, the min-track floor (its only copy; `min_track_ms()` hands it to the renderer's `arm_crossfade` and the skip fire), per-transition state (field docs in `engine.rs`). `effective_duration_ms()` is the ONLY sanctioned duration read on arm/trigger/fire paths: a direct `duration_ms` read misses the bar-snap override on the seek-rearm / EOF-fallback paths. `crossfade_eligible()` is the shared coarse arm gate; `is_crossfade_live(&renderer)` reconciles engine-not-Idle with renderer-Active for `reset_next_track`. Owns neither the renderer `CrossfadeState` nor the `crossfade_duration_shared` atomic (a decode-loop channel)
├── CrossfadeState enum (renderer): Idle / Armed / Active — per-phase data lives inside the variant (incl. the fade `curve` captured at `start_crossfade`); `mem::replace` swaps phases atomically.
├── TransportFade (renderer) — pause/resume/stop and radio-switch fade-in volume ramps, SEPARATE from `CrossfadeState` by design; engages only while the crossfade machine is Idle (see "Transport & Switch Fades")
├── FadeCoordinator (engine, `engine.rs`) — each side mirrors only the fade knobs it consumes: stop, radio-switch and skip on the engine; the PAUSE pair on the renderer, beside its two consumers (`begin_pause_fade`, `start()`'s resume fade-in)
├── PreparedTransitionDirectives — per-transition verdicts (`suppress_crossfade`, `duration_override_ms`, `gap_offset_ms`) the CONTROLLER computes at gapless-prep time from `Song` metadata (which never crosses the engine boundary) and threads into `store_prepared_decoder`; all share the M4 suppress-flag lifecycle (applied by `apply_transition_directives` AFTER the store's internal reset (`discard_next_track`), cleared BY `reset_next_track`, re-derived on every prep)
├── DecodeLoopChannels (engine, `engine.rs`) — exactly the lock-free atomics the primary decode loop reads/writes; `clone_for_decode_loop()` hands the task the same Arcs (an `Arc::ptr_eq` test pins that engine and renderer share them). `live_sample_rate` is engine-only and deliberately excluded
├── GaplessSlot — `decoder` + `source` + `prepared` + `replay_gain` under one `tokio::Mutex`, so the decode loop, async path and `cancel_crossfade` lock together; `replay_gain` rides with the slot so a prep landing mid-blend never clobbers the live blend's `pending_crossfade_replay_gain`. Every taker goes through `take_prepared()` → `PreparedTrack { decoder, source, replay_gain }` and applies THAT `replay_gain`, never the renderer's staged copy (the inline swap via `adopt_gapless_replay_gain`, `load_prepared_track` via `set_pending_replay_gain` before `renderer.init`, `start_crossfade` by re-staging it); the swap's stand-down paths `put_back()` the whole track. The three promotions (`consume_gapless_transition`, `finalize_crossfade_engine`, `load_prepared_track`) share `promote_to_now_playing()`. The inline EOF swap is `try_gapless_swap()` → `GaplessSwapOutcome`; only `Swapped` bumps, and its `bump_for_gapless` is the decode loop's SOLE gapless bump. The swap lands only from the live decode loop (`decode_gen` re-checked under the slot lock and again under the decoder lock) and only while the source generation is where it read it under the slot lock: `bump_for_gapless(seen)` is a compare-and-swap made with the install under the decoder lock, because a skip plan moves the generation without superseding the loop, and bumping past it closed the plan's window and staled its fire (`Superseded` otherwise). Its `GaplessTransitionInfo` carries the generation that bump returned. The completion is a separate task waiting on the engine lock, so the info can be overtaken: `set_source` retires it (its decoder was replaced) and records `source_change_generation`, and both takers (`consume_gapless_transition`, via `decide_transition` and `play()` on a playing engine) drop one stamped below that. A skip plan replaces no decoder, so the swapped-in track it leaves playing is still promoted. The completion task itself is not generation-gated: it still advances the queue after a click or skip that beat it to the lock (open, local/TODO.md)
├── DecodeLoopHandle / SourceGeneration (`generation.rs`) — typed atomic counters whose named methods (`supersede`, `bump_for_user_action`, `bump_for_gapless`, `accept_internal_swap`) label every stop-the-loop / invalidate-callback site
├── LiveStringSlot (`engine.rs`) — `Arc<RwLock<Option<String>>>` newtype for the hot-path live ICY title (`live_icy_metadata`; the decoder's IcyMetadataReader callback writes through `clone_arc()` on its own thread): `reset()` is a non-blocking `try_write`, so the hot-path reset can't drift into a blocking `write()`. Gate any ICY-derived state (now-playing art/title, radio scrobbling) on `is_playing_source(url)` (`self.source == url`; `self.source` is set at the END of `set_source`): during a station switch the UI's `active_playback` flips synchronously but `set_source` runs async after `stop()`, so for a window the engine still streams, and reports ICY for, the PREVIOUS source
└── EqState (eq.rs) — shared atomic gains passed to each StreamingSource
```

## Audio Output (native PipeWire)

One native PipeWire stream via a shared `rodio::Mixer`:
- The renderer owns the music sink (`AudioRenderer::music_sink`, an `ActiveSink`: native PipeWire or the cpal fallback) and rebuilds it at the track's native rate in bit-perfect mode; SFX voices and the volume/title mirror reach it through `MusicOutputBridge`
- `NativePipeWireSink` runs a dedicated `pw_nokkvi_out` thread with its own PipeWire mainloop
- Each track gets an `ActiveStream`: `RING_BUFFER_CAPACITY = 5_000_000` samples (~52 s at 48 kHz stereo, sized for radio jitter) + a `StreamingSource` (a pull-model `rodio::Source`: the PipeWire callback pulls f32 samples) added to the mixer

## Critical Rules

- **Codec registry**: every Symphonia decoder/lookup MUST go through `audio::symphonia_registry::codecs()`, never `symphonia::default::get_codecs()`: the shared registry adds `symphonia-adapter-libopus` to the defaults, and upstream has no Opus decoder (pdeljanov/Symphonia#8, open since 2020), so a direct `get_codecs()` re-breaks `.opus` playback (GH#3). `probe_and_make_decoder(mss, hint, gapless)` owns the shared probe+decoder build; `make_track_decoder(format, gapless)` rebuilds a decoder on an open reader. `gapless` sets `AudioDecoderOptions::gapless`: since Symphonia 0.6 the DECODER drops the container-declared encoder delay/padding, so `read_buffer` does no manual `trim_start`/`trim_end` (one would double-trim). `true` for the primary init in `AudioDecoder::open_input`; `false` for `SfxEngine::decode_wav_stream` and the `ResetRequired` rebuild in `read_buffer` (chained Ogg: the reader rebuilds its tracks in place before signalling, so no reprobe).
- **Symphonia features**: `data/Cargo.toml` sets `default-features = false` to drop the `ape`/`id3v1` metadata readers — they anchor at EOF, so the probe would seek to the end of every seekable source, a blocking range request on `RangeHttpReader` before playback starts. Test `probe_never_seeks_to_trailing_metadata` pins it; keep `id3v2` (skips leading cover-art tags in one jump).
- **Radio receive timeout**: `AsyncNetworkBuffer`'s `Read` waits a shared `RecvTimeout` — `PROBE_RECV_TIMEOUT` (10 s) while `open_input`'s probe reads the first bytes (Icecast joins a listener at the next Ogg page, so first audio can lag the headers ~0.5 s and a `TimedOut` makes the probe fail), then `READ_RECV_TIMEOUT` (500 ms) so the decode loop's generation check stays responsive. Tests `radio_open_waits_for_a_slow_first_audio_byte` / `radio_read_after_probe_returns_promptly_on_a_stall` pin both halves.
- **Stream classification**: the caller says what it loads (`SourceKind::Track` or `Station`, passed to `engine.set_source`; only `load_radio_stream` passes `Station`), and `open_input` records how the bytes arrive (`StreamDelivery`): `Sized` (a length: `RangeHttpReader` or a file), `Live` (always for a station, whose open skips the sizing probes so a Content-Length can't make it finite; for a track, no length AND ICY/Icecast headers), `Unsized` (no length, a queue song: Navidrome's live transcode sends `Accept-Ranges: none` and no Content-Length). The sizing probes (HEAD, a `bytes=0-0` Range probe, a plain GET) stop at the first length. The HEAD's length is its `Content-Length` header (reqwest's `content_length()` is the body's size, 0 for a HEAD), taken only from an answer that doesn't refuse ranges (with `estimateContentLength` Navidrome puts an estimate beside the refusal), so a file opens with the HEAD and the reader's range GET (`a_sized_file_opens_with_a_head_and_its_range_get`). They also stop at the first lengthless answer that says `Accept-Ranges: none`: every probe is a full stream request (with the transcode cache off, its own ffmpeg run), so a live transcode opens with the HEAD and the stream GET (`a_live_transcode_opens_with_a_head_and_one_get`; a lengthless answer without the refusal keeps probing). A queue song whose URL asks for a transcode (`requests_transcode`: a `format` param on `/rest/stream`, which only the Streaming Quality setting adds) skips all of that and opens with ONE GET carrying `Range: bytes=0-<first chunk - 1>` (`open_requested_transcode`; a HEAD would carry no length and, with the server's cache off, start an ffmpeg run thrown away). `classify_transcode_answer` reads its status and headers: a non-2xx (a 3xx the redirect guard won't follow, a 429) and a JSON/XML body are errors with the server's envelope message; `Content-Length: 0` or a 416 is "the server couldn't transcode this song"; a 206 for exactly the range asked, with a `Content-Range` total, is `Sized`, and its body becomes the range reader's first chunk (`RangeHttpReader::with_first_chunk`), so nothing is fetched twice and every later read is a Range request; a 206 for another range (starting elsewhere, or capped short) or with no total is an error. Navidrome answers every range it can serve with a 206, so a 200 is a live transcode or a proxy that stripped the Range header (which would strip every later one too): it is read once through, the bytes already read handed over first, except a 200 with `Accept-Ranges: bytes` whose length fits the first chunk, which is the whole file in hand and stays `Sized`. A once-through answer is `Unsized`, or `Live` when it carries ICY headers, like any track's (`once_through_source`); its first bytes are read before the probe, so an empty chunked body is the same clear error. `X-Content-Duration` comes from that GET. The range reader stores a chunk only from a 206 whose `Content-Range` is exactly the range it asked for, or a 200 for the first chunk of a file that fits in one (`answer_is_chunk`), and only at its full length: another part is an error at once, a short body takes the retry path, on the read path and the read-ahead alike (`a_capped_206_is_an_error_not_a_short_read`, `a_well_behaved_server_is_read_whole_short_last_chunk_included`). Pinned by `a_requested_transcode_opens_with_one_get_and_no_head`, `a_requested_transcode_answered_in_ranges_reads_on_with_range_requests`, `an_empty_answer_to_a_requested_transcode_says_the_server_could_not_transcode` and `a_song_streamed_as_its_file_still_opens_with_the_head_first`. Only `Live` is radio (`is_infinite_stream()`: no backpressure, the jitter prebuffer, the EOF reconnect); an `Unsized` track's EOF ends it like any track's, and a station is never `Unsized`, whatever its headers. The engine records the now-playing stream beside `duration` as one `StreamFacts` (`decoder.rs`: the delivery, the answer's byte length from `AudioDecoder::byte_len` (the range reader's length or the file's size, `None` otherwise), the codec and `offset_secs`, where in the song the stream starts), taken whole by `StreamFacts::of(&decoder)` at every site that records one (fresh `play()` and its Stop-then-Play reopen, a seek's reopen, the three promotions via `promote_to_now_playing`, `GaplessTransitionInfo::stream`, the skip fire's `skip_target`; `set_source` clears it), so a new fact rides every site at once. A track seeks (`seekable()`) when its stream is `Sized` from the song's start (`offset_secs == 0`: range seeks) or when it is a transcode nokkvi asked for on a server that honours `timeOffset` (see "Seek by offset"). For any other (a live transcode the server forced on its own, any live transcode on a server without `transcodeOffset`, a station), `seek` refuses through `seekable()` before it touches a live blend (in a skip blend it judges the incoming, by the facts the fire records in `skip_target`, so a refused seek never cuts the blend short), and `play()` drops a start offset and reopens it (a station too) for a Stop-then-Play instead of `seek(0)`. The UI reads `seekable()` / `is_live_transcode()` off the tick: the progress bar and MPRIS `CanSeek` go off, the seek producers refuse (a toast only for `handle_seek`, by the tick's `StreamStatus::requested_transcode`: "Can't seek in a smaller copy on this server" for a transcode nokkvi asked for on a server without `transcodeOffset`, "Can't seek: your server is choosing this song's format" for one the server chose; Previous with rewind-on-previous steps back instead). Pinned by `a_live_transcode_ends_at_eof_instead_of_reconnecting` (decode loop) and `a_station_without_icy_headers_loads_as_a_live_stream` / `a_station_whose_server_sends_a_length_stays_live` (classification).
- **The queue's track, and whether it is the file**: `seekable()`, `seek_kind()` (`SeekKind::{Range, Reopen, None}` for `nokkvi status`), `is_live_transcode()`, `queue_track_stream()` and `queue_track_source()` pick their track through one private selector, `queue_track()` → `QueueTrack::{Building, SkipTarget, NowPlaying}`: nothing while a skip's decoder builds, the fire's `skip_target` and the blend's incoming source during a skip blend, the now-playing track otherwise. The tick reads them, never `live_codec()` (the engine's own source, the outgoing in a skip blend), and pairs them with the queue's current song only when `StreamSession::song_id_of(queue_track_source)` is that song's id. The engine can be ahead of the queue: an auto crossfade's finalize (and a seek in its finalize gap) promotes the next track a task hop before the completion task moves the queue, and the tick reads the engine, releases it, then locks the queue, so a hard load can land between the two reads. Navidrome serves a transcode finished in its cache like a file (sized, Range works), so a length alone proves nothing: the UI's `StreamOrigin::of` (`src/state/playback.rs`) calls the stream `OriginalFile` only when it is sized at exactly `Song.size` (> 0; a raw file is served at its size on disk, which `Song.size` holds as of the scan the queue's copy came from), `Transcode` when it is unsized or sized at another length (a cached transcode, a same-codec re-encode), `Unknown` when the size is 0 (Navidrome always sends one) or the stream has no length and is no live transcode (a queue song sent with ICY headers), `Pending` when the engine describes no stream (a skip's build) or another song. Only `OriginalFile` can show BIT-PERFECT; `Pending` holds the badge an earlier tick earned (ANDed with the stream built bit-perfect, playing, not radio; never turning it on), while the status and the probe run as on any engaged tick, so a rate change still re-probes at once. The format label (`song_format_label`) is the suffix for the file and for `Pending`, the decoded codec for a transcode, and for `Unknown` the suffix only while the codec belongs to its container (`codec_fits_suffix`: wav/wave/aif/aiff/aifc → `pcm_*`/`adpcm_*`, m4a/m4b/mp4 → aac/alac/mp3/flac/opus/`pcm_*`, ogg/oga → vorbis/opus/flac, mka/mkv/webm → any, otherwise codec == suffix). Nothing refreshes the queue's copy of a song (the pool persists in redb), so a file whose size changed (a retag) loses the badge until Navidrome rescans it AND the song is queued again (accepted: it never gains one). Pinned by `a_skip_blend_reports_the_queue_tracks_codec_and_length_not_the_outgoings`, `a_gapless_swap_carries_the_tracks_answer_length_through_its_pickup` and the `StreamOrigin` handler tests in `update/tests/playback.rs` (`a_cached_transcode_of_a_flac_song_shows_its_codec_and_no_badge`, `a_transcode_within_the_songs_container_family_shows_its_codec`, `a_pending_tick_keeps_an_engaged_badge_and_its_verdict`, `a_tick_whose_engine_already_names_the_next_song_holds_the_verdict`).
- **End of stream**: `next_packet()` returns `Ok(None)` at the real end; `IoError(UnexpectedEof)` means the source ran dry mid-packet (truncated file / closed radio socket) and is treated as EOF at once; `TimedOut` returns to the decode loop at once (so it can check its generation); other I/O errors (RangeHttpReader's are `ErrorKind::Other`) take the bounded retry path.
- **A dropped transcode resumes**: a once-through stream's `AsyncNetworkBuffer` sets its `cut` flag when the body ends in an error (a dropped connection, a proxy cutting it, the 15 s stall) instead of cleanly; the reader still sees an end, and `AudioDecoder::was_cut` tells the two apart. At EOF, before the gap injection and the gapless swap, the decode loop asks `dropped_stream`: a requested transcode (`format` in the decoder's URL; one the server forced is never reopened by nokkvi), `Unsized`, on a server with `transcodeOffset` (the `transcode_offset` channel atomic), cut more than `STREAM_RESUME_END_SLACK_MS` (2 s) short of the whole song (`stream_end_ms`: the offset plus every frame decoded, preroll included). `resume_dropped_stream` then opens the track's `ReopenHints` at that point (`open_within`, bounded by `REOPEN_ANSWER_TIMEOUT` as a seek's reopen is; whole second + preroll, so nothing repeats or skips; the renderer clock counts on) with no decoder lock held across a wait or an open, swaps it in under the lock after re-checking the loop generation, and continues the loop. Bounded: `STREAM_RESUME_ATTEMPTS` (3) per track, each after `STREAM_RESUME_BACKOFF_MS` (0 / 500 / 1500 ms); a resumed stream that decodes `STREAM_RESUME_REFILL_MS` (30 s) before its next drop earns them back, so a server cutting every stream gets at most three more requests per song. An answer in another format, or no attempts left, gives up: the cut decoder stays in place at its end, the normal EOF path runs (swap or completion, as before), and the `stream_lost` channel atomic tells the UI tick once (`take_stream_lost` → `toast_warn` "The server stopped sending this song."), set only by the loop still current (a track change or seek during the last attempt supersedes it, and the word would land on what plays then) and cleared by `set_source`. A clean early end, a station, a server-forced transcode and a sized file keep the plain end. Tests: the clock server's `cut_live_answers` and the `a_dropped_transcode_*` / `a_transcode_*` / `a_drop_at_the_songs_end_is_its_end` engine tests.
- **Track changes** (engine-lock discipline: CLAUDE.md "Track changes and the engine lock"): load a queue song through `StagedSong::load` (`services/playback.rs`: load with the song's tags, arm an optional start offset, then `StageStart::Play` or `Cue`), which calls `engine.load_track_with_rg(url, rg, expected_duration_ms)`: `set_source` first, then the ReplayGain stash (`set_source`'s teardown can promote a live skip blend, which restages the promoted track's tags). `expected_duration_ms` carries the server's track length into the decoder (see "Probed Duration"). The controller's play paths wrap the load in `stage_and_name`, which discharges the queue mutation's reset and, once the engine took the song, names it on the navigator, all under the engine lock (engine before navigator is the lock order everywhere). The skip-fade fallbacks and `recover_stalled_crossfade` load directly: the queue already names their target. A stream URL comes only from `StreamSession` (`QueueService::stream_session()`), which exists only when both the server URL and the credential do; the play paths check it before they move the queue. A session snapshots the Streaming Quality setting, which lives on `QueueService`: seeded from `SettingsManager` at construction, then pushed on every settings load by `PlaybackController::apply_player_settings` (the UI's `handle_player_settings_loaded` hands it every engine setting) through `push_stream_quality`, under the engine lock. A change in what the setting asks of the server (`StreamQuality::effective`: a Max Bitrate change under Original is none) resets the prepared next track once, except while an AUTO crossfade blends (`auto_crossfade_live`): the reset would cancel the blend back to its outgoing, and its prepared track has already left the slot as the incoming, so the prep after the blend reads the new setting. A skip blend is spared by the reset anyway, which still drops a prep of the song after its target. The song playing keeps its stream, a blend's incoming included. The completion callback and Next / Previous take their session before the engine lock and re-stamp it with `QueueService::stream_quality()` once they hold it, so a push landing in between can't leave the next load on the old setting. `stream_url(&Song)` appends `format` + `maxBitRate` right after `id` when `types::stream_quality::stream_params` picks a transcode for the song (never `format=raw`, never a cap alone, never `estimateContentLength`); a pool miss (`stream_url_for(id, None)`) asks for the file.
- **Seek by offset** (a transcode nokkvi asked for: `requests_transcode` on the PLAYING decoder's URL, and the engine's `transcode_offset` flag, set from the login's `getOpenSubsonicExtensions` probe through `PlaybackController::apply_server_extensions` (`transcodeOffset`); every login builds a new engine, so it starts off and a failed probe leaves it off). `seek` asks how the decoder it lands on moves (`decoder_seek` → `DecoderSeek::{Range, Reopen, Unavailable}`, read from the decoder itself, since after an inline gapless swap whose completion has not run it is already the next song while `self.source` / `self.stream` still name the outgoing). A `Reopen` runs in THREE steps so the engine lock is never held while the server answers (`PlaybackController::finish_begun_seek`; `CustomAudioEngine::seek` runs the same three inline for the deferred skip seek and the tests). (1) `begin_seek`, under the lock: `reopen_candidate` picks the decoder by the engine's facts (the skip blend's incoming, else the playing decoder; a range-seeking track gets no ticket and seeks right there, `SeekBegun::Done`), nothing is stopped, and it hands back a numbered `ReopenTicket` (`SeekBegun::Reopen`) while `reopening` records the serial, the target and the source generation; `position()` reports that target meanwhile, as it does a settling seek's, so the clock doesn't snap back while ticks run. (2) `ReopenTicket::open`, with the lock RELEASED: it waits for the decoder's lock, copies its `ReopenHints` (its own URL, so its `format` / `maxBitRate` stay what it opened with whatever the setting says now; its kind, expected length and file size) and runs `ReopenHints::open_within`: `AudioDecoder::open_at(url, target / 1000)` (`with_time_offset` adds `timeOffset` as a whole number, the server reads anything else as 0), then `land_on` (the milliseconds past that second dropped through the seek preroll, `skip_ms`; a sized answer from the song's start range-seeks). The probe's later reads (`PROBE_RECV_TIMEOUT`, 10 s each), a sized Ogg's tail fetch and that range seek all block, so the open runs on a task of its own and the WHOLE of it, the wait for the decoder's lock included, is bounded by `REOPEN_ANSWER_TIMEOUT` (5 s; past it `NoAnswer`, the task aborted; `a_reopen_stalled_after_its_first_bytes_gives_up_in_its_own_time`). The old stream plays on and everything else runs as usual: an armed crossfade fires and blends, a blend finalizes, the track can end, the user can skip or stop. (3) `finish_seek`, under the lock again: the answer lands only while it is still the newest seek on the same track: its serial is the one `reopening` holds (a newer `begin_seek` replaced it; `set_source`, stop and every promotion clear it, wherever a settling seek is cleared), the source generation has not moved, and no relative seek is settling since. Otherwise it is dropped without a word, so a blend that finished into the next song during the wait is an ordinary track change (`a_reopening_seek_waits_for_the_server_without_the_engine`, `a_track_change_during_a_seeks_reopen_drops_the_seek`, `a_newer_seek_replaces_one_whose_reopen_is_out`, `a_settling_seek_replaces_one_whose_reopen_is_out`, `a_stop_during_a_seeks_reopen_drops_the_seek`). Held under the engine lock instead (the first design), that wait stalled a blend's finalize, the tick and MPRIS, and needed a held crossfade trigger and a special case per symptom. One gap is left, a task hop wide: the render thread signalled just before `finish_seek` took the lock, its callback still queued. A blend it finished is finalized (`finish_a_blend_the_renderer_ended`, see "Seek in the finalize gap") and the seek dropped; after any other signal (`engine_signals_sent` moved since the ticket) the source generation moves so a queued callback is dropped, and a blend the renderer fired that the engine never heard of is abandoned by the seek like any auto blend (`a_blend_fired_during_a_seeks_reopen_is_abandoned_by_the_seek`, `a_blend_that_ends_during_a_seeks_reopen_is_finalized_not_undone`). Only then does the seek end the blend, stop the loop and `land_reopen` the new decoder (refused, with the seek dropped, when the playing decoder is no longer the planned one: the loop swapped in the next song meanwhile), so a slow server costs no silence and the renderer clock (`seek_into`, which also rebuilds the output for a changed format) reads the target. `current_format` / `live_sample_rate` follow the new stream at once (they describe what the decoder and output play, which the crossfade gate and the next load compare); its `StreamFacts` go to the now-playing track or, in the gapless window, ride the pending `GaplessTransitionInfo`. The decoder classifies the one answer (`open_requested_transcode`, then the probe): unsized means the offset was honoured; a sized answer is the song's own file, which ignores the offset, when its length is exactly the song's size on disk (`expected_file_size`, `Song::expected_file_size`, threaded beside `expected_duration_ms` through `StagedSong::load` → `load_track_with_rg` → `set_source`, the gapless prep, the skip build and the reopen) or when its probed length runs the whole song (`sized_answer_is_the_file` → `answer_starts_at_song_start`, which can't tell without a whole-song or a probed length): another length proves nothing, since the queue's copy of a song keeps the size of its scan and a retag changes the file's (`a_reopen_answered_by_the_file_at_a_stale_size_lands_on_the_target`). The file's `offset_secs` goes back to 0, the range reader reads on from the file's own URL without `timeOffset` (`RangeUrl`; the server answers the offset URL by its own rules later) and `land_on` range-seeks it; any other sized answer is a cache entry for that offset (the offset is in Navidrome's cache key) and is treated as live: its bytes start at the offset, so the next seek reopens again. The UI's `StreamOrigin` trusts the size alone, so a file at a stale size seeks right but shows no badge, and a server length short of the song's by over half the offset can make a cache entry pass for the file (both rare, accepted). An offset stream's `duration` is the whole song (`X-Content-Duration`, else the metadata), never its probe, with no seek scale. An answer with no audio in it (an empty body, a 416, a headers-only Ogg the probe finds no audio in, told by the bytes actually read up to `PAST_END_ANSWER_MAX_BYTES`, never a `Content-Length`; an MP3's ID3v2 tag alone, which Navidrome sends past the end, is told before the probe by `holds_only_tags`, or Symphonia logs an ERROR on it) is the song's end only at an offset within `PAST_END_SLACK_MS` (2 s) of the whole song's length or beyond (`offset_is_past_end`): `open_at` returns `StreamPastEnd`, the playing decoder ends where it is (`end_here`), the renderer jumps to the end, and the restarted decode loop takes the EOF path (gapless swap or completion), as at a natural end, no error; `track_ended_by_seek` then holds until the next source, promotion, play or seek, and `prepare_next_for_gapless` stands down while it does (the completion's own load would throw the prep away after the server started its transcode). Anywhere else it is a failed transcode (`NoAudioFromOffset`), like any other failure: the old decoder, a live blend and the renderer are untouched, the old stream plays on where it was, and the engine keeps a `SeekFailure` (`Busy` for a 429, typed `ServerBusy`; `NoAnswer` for no answer in time or a request that never reached the server, typed `NoAnswer`; `Other`) for the UI tick (`take_seek_failure` → one `toast_warn`, `seek_failure_text`: "Couldn't seek: the server is busy. Try again in a few seconds." / "Couldn't seek: the server didn't answer." / "Couldn't seek in this song."; the detail goes to the log only). A server length too long by more than `PAST_END_SLACK_MS` makes a seek between the real end and the stated end less 2 s fail with "Couldn't seek in this song." (its empty answer reads as a failed transcode; accepted). Identity never moves: `self.source` stays the track's own URL (`is_playing_source`, `set_source`'s early return, `song_id_of`, the gapless guard and `queue_track_source` all compare base URLs), the offset lives in `AudioDecoder::offset_secs` and `StreamFacts::offset_secs`, `init(url)` reopens a decoder open at an offset, and a seek moves the source generation only to drop a render-thread signal it outlived (above, and the finalize gap). Stop then Play reopens the base URL (`play()` reopens any decoder that isn't sized from the song's start), and a start offset (`pending_start_ms`) goes out with the FIRST open (`open_at(source, offset)`, one request), range-seeking instead when the answer is the file; it is cleared only once the renderer took the track, so a failed open or output leaves it armed, except an answer with no audio from it (`StreamPastEnd` or `NoAudioFromOffset`), which starts the song from its top instead (kept, every Play would fail the same way); a busy server or no answer fails the Play and keeps it. Tests: the clock server in `decoder.rs` tests (`spawn_clock_server`, a WAV whose samples hold their own song time, `ClockReply`, with an answer delay, a header-duration override and a 44.1 kHz file) and the `*_reopen*` / `*_offset*` engine tests.
- **Seek precision**: the clock trusts that audio resumes exactly at the seek target, so `AudioDecoder::seek` makes it true. `seek_mode_for` picks `Accurate` for MPEG audio (MP1/MP2/MP3: no timestamps, and Symphonia's coarse seek spreads the byte length evenly over the duration, so a VBR file landed seconds off while reporting the estimate as where it landed); it counts frame headers from the read position (from the first frame for a seek back), reading those bytes but decoding none. Every other container stays `Coarse` (it lands on a real timestamp; an accurate FLAC seek without a SEEKTABLE decodes from the start), and only the coarse target goes through `seek_scale`. `seek_preroll_frames` (from `actual_ts`/`required_ts`, in the track's time base, negative = encoder delay that the gapless decoder already drops) is dropped from the front of the decoded output, error-arm silence included. Tests `a_vbr_mp3_seek_lands_on_its_target` / `a_vbr_mp3_seek_to_zero_keeps_the_whole_opening` (fixture `testdata/vbr_silence_then_noise.mp3`).
- **Gapless join clock**: the inline swap runs when the DECODER reaches the join, with the outgoing's tail (up to the cushion, plus any injected gap) still in the ring. It resets the position through `reset_position_at_join`, which records the ring's occupancy as `join_lead_samples`; `StreamHandle::position_ms` subtracts it, so the joined track's clock reads 0 until its first sample plays. Every other reset zeroes the lead. Test `a_gapless_join_starts_the_clock_when_the_join_is_heard`.
- **Relative seek**: `PlaybackController::seek_relative` reads `engine.position()`, computes the target and begins the seek under ONE engine-lock acquisition (a range seek runs whole there; a reopening one releases the lock for the server's answer, see "Seek by offset"), then returns where it LANDED (re-reading `position()`, so a refused seek honestly reports no movement). Calls queued behind one another each read the previous one's result, which is what makes a held key accumulate. On a track whose seek reopens the stream (`engine.seek_reopens()`, with a known duration) it does not seek: the engine holds the target (`defer_seek`), `position()` reports it, and one tracked `seek_settle` task (`run_seek_settle` over `take_settled_seek`) runs the seek once `SEEK_SETTLE` (300 ms) passed with no further repeat, so a held key costs at most two transcodes on the server instead of one per repeat (the OS repeat delay can outlast the settle, so the first press may fire its own); any seek, `set_source`, stop and EVERY promotion (`promote_to_now_playing`: an auto blend's finalize and `load_prepared_track` don't move the source generation) drop a settling one, and a generation move (the inline swap, a skip plan) does too. The arithmetic and the clamps live in the controller; the settle state lives in the engine (`settling_seek`). The low clamp floors at 0 and skips the engine entirely when the target equals the base — `renderer.seek` rebuilds the output stream on every call. The high clamp is the engine's own `min(duration)`, so a jump past the end ends the track exactly as dragging the slider there does.
- **Pulled-queue cue**: `PlaybackController::cue_pulled_queue` reloads the pulled current song with a one-shot `pending_start_ms` resume offset: it plays at once if the engine was playing, otherwise it stays cued for the next Play. The offset is consumed in `play()`'s fresh-start branch (seeks the decoder BEFORE the renderer starts, so no position-0 audio renders; a transcode that seeks by offset opens at it instead) and cleared by `set_source` ABOVE its same-source early return. A pull replaces the queue through `set_queue`, which only mutates the queue and leaves the engine playing the pre-pull song, so the re-cue is required. Never through `plan_click_play`: a skip-fade would blend the pulled song in from position 0, and the saved offset could only land afterwards as an audible jump.
- **Next-track reset**: `reset_next_track()` clears the prepared decoder, disarms crossfade, and clears every per-transition directive: the suppress flag, the bar-snap `duration_override_ms` (restoring `crossfade_duration_shared` to the global), and the pending gap. Queue mutators return the `#[must_use]` `NextTrackResetEffect` (backend-services.md), discharged via `apply_to(&engine)` or, with the engine lock held, `apply_locked(&mut engine)`. The reset cancels a live AUTO blend and spares a live manual-skip blend, whose incoming is the queue's current track, not a next track (see "Manual-skip crossfade"). Every reset moves the engine's `next_track_epoch`: a gapless prep snapshots it before it peeks the queue and stores through `store_prepared_decoder_if_current`, which refuses a build that outlived a reset (it would install the old queue's next track); the UI tick reports it and the UI reopens its `gapless_preparing` latch when it moves, so a queue edit or setting change after the 80% prep gets a fresh prep instead of a hard cut. `store_prepared_decoder`'s own replace step (`discard_next_track`) leaves the epoch alone, or every store would re-trigger the prep.
- Decoupled render thread: 20 ms intervals (50 Hz), handles crossfade tick + completion detection.

## Network Resilience (issue #9)

Layered subsystems keep finite HTTP streams playing on shallow networks:

- **Background read-ahead** (`range_http_reader.rs`): `prefetch_loop` keeps a sliding window of `PREFETCH_WINDOW_CHUNKS` chunks ahead of the read cursor, topping up when the lead drops to `PREFETCH_LOW_WATERMARK_CHUNKS`. Spawned lazily by `maybe_spawn_prefetch()` on the first forward-sequential read (current chunk == previous + 1), so the FLAC init-probe's binary-search seeks never spawn a task chasing a bouncing cursor. A const assert (`1 + PREFETCH_WINDOW_CHUNKS + EXPECTED_BEHIND_CHUNKS <= MAX_CACHED_CHUNKS`) guarantees the LRU can never evict the live window — keep it satisfied when resizing any of the three. The synchronous seek-time prefetch is a separate, unchanged path.
- **Decode cushion** (`engine.rs`): the decode loop buffers `CUSHION_MS` ahead (TIME-based, scaled by frame rate, grown for long crossfades); backpressure releases at `CUSHION_MS / BACKPRESSURE_RELEASE_DIVISOR`.
- **Pause-and-rebuffer** (`renderer.rs`): pure state machine `rebuffer_action(RebufferInputs, &mut RebufferLatch)` → `RebufferAction` driven from `render_tick`. Watermarks are TIME-based (enter below `REBUFFER_ENTER_MS`, resume at `REBUFFER_RESUME_MS`), converted to samples per-format via `frame_rate`. Fixed-SAMPLE budgets once deadlocked hi-res playback: at 96k/192k they shrank in time until rebuffer entry sat above the decode backpressure-release point, freezing the ring. Compile-time interlocks encode the ordering (`REBUFFER_ENTER_MS * BACKPRESSURE_RELEASE_DIVISOR < CUSHION_MS`, `REBUFFER_RESUME_MS < CUSHION_MS`, `REBUFFER_ENTER_MS < REBUFFER_RESUME_MS`) — keep all three satisfied when changing any of these constants. Finite streams only (sized or unsized): never radio, never mid-crossfade. `MAX_REBUFFER_TICKS` is the dead-socket safety valve.
- **Latch discipline**: `reset_rebuffer_latch()` resets the `RebufferLatch` (`rebuffering` / `primed` / `ticks`) on every fresh-ring transition — start, stop, seek, and `finalize_crossfade` (carrying a stale `rebuffer.primed` across a sample-rate change is the one path that re-creates the deadlock; test `finalize_crossfade_resets_rebuffer_latch`). `pause()` deliberately clears only `rebuffering`. The latch primes once the ring first reaches the resume target, so a cold track start cannot false-pause at 0:00.

## Volume & Fade Application

Dual-path user volume: PipeWire native (preferred) or software fallback.

- **PipeWire-native** (`pw_volume_active = true`): software volume at 1.0; SfxEngine sends cubic (`v³`) to PipeWire over IPC.
- **Software fallback**: exponential amplitude curve (`perceptual_volume`), per-sample exponential smoothing (~5 ms EMA) for anti-aliasing.

The fade is a **separate channel from user volume**: `StreamHandle.fade_coeff` atomic + a `smoothed_fade` EMA in `StreamingSource`, applied **linearly** on BOTH arms: non-bit-perfect output is `sample · smoothed_volume · smoothed_fade · smoothed_norm_gain` (`smoothed_volume` is an EMA toward `perceptual_volume(user_vol)`); bit-perfect is `sample · smoothed_fade` with the `UNITY_SNAP_EPSILON` snap at `fade_coeff ≥ 1.0`. Never route a fade through the `volume` atomic: user volume is re-curved by `perceptual_volume`, and a re-curved fade put every default-path midpoint at `perceptual(0.5)` ≈ −30 dB per stream, a near-silence hole mid-blend (the historical crossfade bug).

- `StreamingSource::new` seeds BOTH the `fade_coeff` atomic and `smoothed_fade` from `StreamSettings::initial_fade`: 0.0 for the crossfade incoming stream, 1.0 for fresh play/seek streams (the renderer's `primary_stream_settings()`; the crossfade build overrides the fade and `feeds_visualizer`). Hardcoding the smoother at 1.0 plays the first ~5 ms of every crossfade incoming at near-full gain (onset burst).
- `tick_crossfade` writes `fade_gains(curve, progress)` (`audio/fade_curve.rs`) to both streams' `fade_coeff`; the curve is captured into the renderer's `Active` variant at `start_crossfade` (a mid-fade settings change never tears an in-flight blend): **Equal Power** (default — `cos`/`sin`, power-sum 1, flat loudness for uncorrelated tracks), **Constant Gain** (the historical `cos²`/`sin²`, amplitude-sum 1 — equal-power only for correlated content, ~3 dB midpoint dip otherwise), **Linear**. Fade-in endpoints are exactly 1.0 — the unity snap depends on it.
- `fade_coeff → 1.0` resets at BOTH `finalize_crossfade` and `cancel_crossfade`; in `cancel_crossfade` the reset is **unconditional, outside the `!self.paused` guard** — resume (`start()`) restores only `volume`, so a paused-path cancel would otherwise strand the restored outgoing at reduced gain.
- A mid-crossfade `set_volume` pushes `stream_volume()` to BOTH streams' `volume` atomics **unconditionally** (the tick writes only `fade_coeff`; gating the push on `!paused` would permanently lose a volume change made while paused mid-blend).
- **De-click onset ramp** ("Smooth Track Starts", default on): non-bit-perfect streams seed the user-volume smoother at 0 (`smoothed_volume: if smooth_starts && !bit_perfect { 0.0 } else { volume }`) so the existing EMA ramps 0 → target over ~23 ms from the first sample. The volume EMA advances on **real samples only** — clocking it on ring-starvation fills burns the ramp during the decoder's fill latency and ships the click anyway. `smoothed_fade` stays pull-clocked (the fade envelope is renderer-wall-clock-driven). Bit-perfect streams keep an instant, honest onset.

## Transport & Switch Fades

`TransportFade` (renderer): `Idle / FadingOut{Pause|Stop} / FadingIn / SwitchFadeIn` — short per-stream volume ramps (20–500 ms, default 100 ms) replacing the mid-waveform atomic flips on pause/resume/stop, ticked by the 20 ms render thread. Kept SEPARATE from `CrossfadeState`; `transport_fade_engageable()` refuses while a crossfade is armed/active (never fight a blend), on a bit-perfect stream (its arm reads only `fade_coeff`, so a volume ramp is an inaudible delay; ramping `fade_coeff` outside a crossfade would break bit-identity), and on a drained ring (nothing audible to fade). "Fade on Pause / Resume" and "Fade on Stop" both default OFF.

- **Guard-lift**: `begin_pause_fade`/`begin_stop_fade` set `self.paused = true` IMMEDIATELY (freezing the completion gate, the rebuffer path, and the armed crossfade trigger below `render_tick`'s early-return); `tick_transport_fade()` runs ABOVE that early-return. Deferring `paused` until ramp completion would let a pause near end-of-track advance the queue mid-ramp.
- **Settle tick**: the ramp-floor tick writes volume 0.0, sets `settling`, and returns; the NEXT tick applies the real `pause()`/`silence_and_stop()`. Applying the end action in the same tick cuts at the source EMA's pre-floor gain — up to a full-amplitude click at the 20 ms minimum.
- A per-fade **generation token** discards stale completions; an interrupting ramp seeds `from` off the stream's last-written `volume` atomic so the level never snaps.
- `engine.stop()` runs the out-ramp with a bounded wait (ramp + 250 ms deadline) BEFORE `stop_render_thread()` — the render thread is what drives the ramp. Stop-from-paused skips the ramp entirely (the early-return already froze the stream). `set_source`'s internal stop calls `stop_without_fade()`: track changes belong to "Fade on Skip", never to "Fade on Stop".
- `renderer.init()`'s gapless-reuse branch restores the reused primary's `volume` when it abandons an in-flight ramp — the one cancel site that neither restores the volume nor rebuilds the stream.
- **Radio-switch fade** ("Fade Radio Switches", default off): both switch edges run a fixed `RADIO_SWITCH_FADE_MS` (250 ms) out-ramp via the shared `run_bounded_out_fade`, then arm a one-shot fade-in request consumed at the next fresh stream build (in `init()`, before `play()`'s prebuffer can feed the mixer a full-gain sample). Edge detection differs: queue→radio is caller-known — the UI radio-start paths call `engine.stop_for_radio_switch()` (flag off ⇒ delegates to `stop()`, byte-identical to the historical explicit stop), then `engine.load_radio_stream(url)`; radio→queue is engine-known (`stream_is_infinite` still reflects the outgoing at `set_source` entry). Finite→finite track changes stay instant.
- `SwitchFadeIn` is **first-audio-triggered, not wall-clock**: it holds the fresh primary silent until the mixer pulls real samples past a `baseline_samples` snapshot, then ramps 0 → target (a wall-clock ramp would finish during the radio prebuffer silence and pop at full gain when audio arrives). `pause()` **re-arms** it with a fresh baseline instead of cancelling — the radio jitter-prebuffer dance re-pauses repeatedly, and the pre-jitter trickle of real samples must not silently burn the ramp; `start()` leaves it alone. A bit-perfect fresh stream drops the request.
- **Boundary skip fade** ("Fade on Skip" = Boundary Fade, also the blocked-blend fallback): `run_skip_out_fade` delegates to the same bounded out-ramp with the skip duration, then the normal load proceeds. No separate `TransportFadeTarget::Skip` variant exists — its end action would be identical to `Stop`.

## Volume Normalization & ReplayGain

The renderer resolves a `NormalizationConfig` per track from `volume_normalization_mode`. A static gain (`Off` = unity, `Static(g)`) is applied INSIDE `StreamingSource::next` (after volume + fade, before the chain's limiter; the visualizer and level-meter taps stay pre-gain; never on bit-perfect streams); AGC is a processor in the `RodioOutput` chain; every non-bit-perfect chain ends in `limit(LimitSettings::dynamic_content())`. **Per-track gain on one stream**: `ActiveStream` counts samples written and owns the producer of a lock-free `GainSwitch` queue `(ring index, gain)` whose consumer the source holds; `schedule_norm_gain(g)` queues a switch at the index the NEXT written sample takes, and the source applies it when its never-reset `ring_read` counter reaches that index (eased ~5 ms like the volume EMA, so a mid-waveform step can't click). Several can be queued (tracks shorter than the ring's lead). Never use `samples_consumed` for this: it resets at every inline swap, ~1 s before the swapped-in track is heard.

**Staging**: primary loads stash the incoming track's ReplayGain via `load_track_with_rg(url, rg, expected_duration_ms)`; the UI radio starts load through `load_radio_stream(url)`, which stages no tags (a stream is untagged, so it builds at the fallback dB or AGC, never the last queue song's or a promoted blend's level); the crossfade decoder uses `set_pending_crossfade_replay_gain()` before its stream is built. `finalize_crossfade` makes the staged crossfade RG both `current_replay_gain` AND `pending_replay_gain` (else a Stop-then-Play after a crossfade rebuilds at the previous track's level). `renderer.seek` rebuilds from `current_replay_gain`, the playing track's tags, which every stream build and inline swap records. The inline swap's `adopt_gapless_replay_gain` (fed the slot's tags) records them as `current_replay_gain` and switches the live stream's gain at the join, leaving `pending_replay_gain` alone: the decode loop reaches it without re-checking its generation, so a superseded loop could overwrite a newer hard load's stash. The tags ride in `GaplessTransitionInfo`, and `consume_gapless_transition` (engine lock held) restages them as `pending_replay_gain`, so a Stop-then-Play of the joined track rebuilds at its gain.

**Stream reuse**: both gapless paths that keep the live stream (the inline swap, `gapless_swap_allowed`, and `init`'s reuse branch) ask `needs_own_stream_for(tags)`, true only when a gain switch can't follow: AGC switching on, off or retargeting (`NormalizationConfig::can_follow`), or a bit-perfect mode change since the build. A static-gain change in any mode (Track gain, Album gain, peak clamp, fallback dB) is just a gain switch, so ReplayGain modes stay gapless. A refused swap reports `GaplessSwapOutcome::NeedsOwnStream`; the end-of-track `load_prepared_track` stages that track's tags as `pending_replay_gain` before `renderer.init`, which builds a fresh stream at them (a cross-rate auto-advance too), and `init`'s reuse branch records the staged tags and switches the gain. `Song::replay_gain` reads the Subsonic `replayGain` object or the native `/api/song` flat `rg*` fields.

## Bit-Perfect

`BitPerfectMode` (`types/player_settings/playback.rs`): tri-state `Off` / `Strict` / `Relaxed` (legacy bool records deserialize `true → Strict`, `false → Off`). The engine mirrors it in `crossfade.bit_perfect_mode` (the `CrossfadeCoordinator` field `crossfade_eligible` reads) through `set_bit_perfect`, which also delegates to `renderer.set_bit_perfect` and, on a real mode change (the renderer reports the flip), runs `reset_next_track()`: the flip changes crossfade eligibility, so a crossfade armed under the old mode would fire against a gate that now refuses it and orphan the blend. An unchanged mode is a no-op, so a routine settings save never disturbs an in-flight transition.

- **Active condition**: `bit_perfect_active() = mode.builds_bit_perfect() && pw_volume_active` — both `Strict` and `Relaxed` build bit-perfect; it requires PipeWire-native volume so no software gain touches the samples.
- **DSP bypass** (`StreamingSource::next`): bit-perfect skips EQ entirely and, at unity, returns the raw decoded sample untouched (no software volume, not even the unity-curve multiply) so a settled body stays bit-identical. During a Relaxed crossfade the `fade_coeff` atomic carries the fade coefficient, applied directly (already shaped by the tick's selected curve — not re-curved through `perceptual_volume`).
- **Honest badge**: `current_stream_bit_perfect` is captured at stream-build time, not read live, so a mid-track toggle can't claim BIT-PERFECT for a stream still on the DSP path. Each `ActiveStream` records its own build-time `bit_perfect`; `finalize_crossfade` stamps the promoted stream's value and `cancel_crossfade` the restored outgoing's, never the live mode (a skip blend survives a mode flip, and a flip cancels an auto blend only after the renderer took the new mode). The UI shows the badge only for the song's own file (`StreamOrigin::OriginalFile`, see "The queue's track, and whether it is the file"): never for radio, a transcode, or a stream whose origin can't be told.
- **Crossfade gate**: `crossfade_blocked(current, incoming)` matches on `enforced_bit_perfect_mode()` (the selected mode while `bit_perfect_active()`, `Off` otherwise): `Strict` → always blocked, `Relaxed` → blocked only on sample-rate / channel-count mismatch (the DAC can't re-clock mid-blend), `Off` → never. Both crossfade triggers gate on this one method with the same `(current, incoming)` pair.
- **Fades & trims stand down**: bit-perfect streams refuse transport/switch/boundary fades (see "Transport & Switch Fades"), and BOTH silence-trim halves (leading trim and the trailing early trigger) stand down under Strict AND Relaxed — gated on `builds_bit_perfect()` (mode intent, not live `pw_volume_active`, so the verdict can't flap with the output backend). Dropping or never playing decoded samples is a content change.

## Probed Duration

`sanitize_probed_duration(probed_ms, expected_ms)` (`decoder.rs`) cross-checks Symphonia's probed length against the server's track length (threaded in as `expected_duration_ms`). When the probe wildly disagrees with the server metadata (a VBR MP3 with no Xing/VBRI tag gets a 17-frame bitrate extrapolation; before Symphonia 0.6.1 the Xing/CRC bug #516 did the same, ~30 min for a ~4 min MP3), the server value wins. The duration is read from `Track::duration` (0.6 defines `num_frames` as unit-less). For an `Unsized` track (a live transcode, see "Stream classification") the expected length is the response's `X-Content-Duration` header first (Navidrome sets it on every `/rest/stream`), then the caller's metadata: the probe reads 0 from a stream with no Xing header and no byte length. `compute_seek_scale(probed_ms, sanitized_ms)` then derives `seek_scale` (1.0 unless the probe was overridden) so seeks land at the right wall-clock position against the corrected timeline.

## Equalizer

- 10-band graphic EQ: `EqState.gains: Arc<[AtomicU32; EQ_BAND_COUNT]>` (`eq.rs::EQ_BAND_COUNT = 10` is the single source of truth for every gain-array width, including the `eq_gains` fields on the settings/types side), `EqProcessor` per-stream biquad bank
- Bands: 31 Hz–16 kHz (ISO standard center frequencies), ±12 dB clamp (`EQ_GAIN_DB_MIN` / `EQ_GAIN_DB_MAX`, shared with the EQ sliders and the settings load-time `validate`; NaN-safe via `clamp_gain`).
- Headroom: −1 dB applied only when the max boost > 0 dB.

## Crossfade

Two concurrent `ActiveStream`s. Guards: both durations known (non-zero), both songs ≥ the configured minimum track length (`crossfade_min_track_secs`, 0–60 s, default 10 s), duration clamped to `min(xfade, shorter / 2)`. A controller-side policy verdict (`audio/crossfade_policy.rs::crossfade_decision`, computed at gapless prep from Song metadata: min-track floor + the opt-in same-album continuity gate `crossfade_album_gapless`) rides down as the per-transition suppress flag (set by `store_prepared_decoder` after its internal reset and BEFORE the arm; lifecycle in PreparedTransitionDirectives above), gated at BOTH trigger sites (`arm_renderer_crossfade`, which also covers rearm-after-seek, and `try_start_crossfade_transition`) so a suppressed transition falls through to the gapless join. The position-based trigger in `render_tick` is synchronous (CLAUDE.md "Crossfade trigger must be synchronous"). Cancellation splits by state: `cancel_crossfade()` clears `Active` (the in-flight stream), `disarm_crossfade()` clears `Armed` (metadata only); pair them when both must clear (engine-level `cancel_crossfade`, renderer `stop`). `renderer.seek` calls only `cancel_crossfade()`, so a pending gapless `Armed` state survives the seek and the position trigger can still fire. An engine `seek` that cancels a live AUTO blend returns `SeekOutcome::AbandonedAutoCrossfade` (`start_crossfade` took the prepared decoder out of the slot and the cancel dropped it); `PlaybackController::seek` then calls `prepare_next_for_gapless` with the engine lock released, because the UI's `gapless_preparing` latch reopens only on a song change or a `next_track_epoch` move, and a blend cancel causes neither.

Eligibility is the shared `CrossfadeCoordinator::crossfade_eligible()` predicate (`enabled || bit_perfect_mode == Relaxed`: the Relaxed gate lets same-format tracks blend under bit-perfect, see "Bit-Perfect") that all three arm/trigger sites (`store_prepared_decoder`, `rearm_crossfade_if_prepared`, `try_start_crossfade_transition`) call; `crossfade_blocked()` then vetoes ineligible format pairs. **Finalize before EOF**: `try_finalize_crossfade(is_eof, renderer_fade_active)` finalizes the `Active` phase as soon as the renderer reports its fade is over, even before the outgoing decoder hits EOF: past the fade the outgoing is silent, so its tail is discarded. Requiring `is_eof` left a torn state for seconds on coarse VBR seeks (renderer promoted the incoming, engine still `Active`), then promoted an already-EOF decoder, instantly skipping the next track. The decode loop's `decoder_eof` signal is generation-gated so a loop superseded mid-`read_buffer` (which can block for seconds) can't store EOF for a no-longer-current track.

**Manual-skip crossfade** ("Fade on Skip" = Crossfade) runs in three phases across the lock boundary (no engine lock held across decoder creation):
1. UNDER the engine lock, the queue layer sequences the skip (Next/Previous: the navigator's `skip_to_song`, for cursor, history, consume) and calls `engine.plan_skip_fade()`: it cancels any live blend, skip blends included (cancel-live-first: nothing can finalize during the build; a second Next inside a skip blend restores the first track for the new build), voids the pre-skip prepared transition (`reset_next_track`), calls `bump_for_user_action`, and latches the generation-keyed `skip_fade_pending` window.
2. Controller `complete_skip_fade` builds the incoming decoder with NO locks held (`AudioDecoder::default() + init()`, registry path).
3. `engine.crossfade_to_next` re-locks and fires the blend `Active` **directly** (no `Armed` hop; the preserved invariant is renderer-Active-before-engine-phase + cancel-live-first). Bypassing `arm_crossfade`, it re-applies `crossfade_blocked`, takes its length from the same pure `crossfade_length_ms` (known durations, min-track floor, `shorter/2`) and clamps it to the remaining audio (`skip_fade_duration_ms`: a fade never outlives the outgoing).

- **Supersession** is two-fold: `skip_fade_seq` (only the latest skip completes; `next`/`previous` stamp it only for a skip that moved the cursor or the engine, `NextOutcome::{Played, FadePlanned, Drained}` / `PreviousStep::{Played, FadePlanned}`, so a no-op Next at the queue's end or a Previous with nothing to step back to lets an in-flight build land its target) and a `source_generation` snapshot taken after the plan's bump (any competing user action wins; the fire bumps AGAIN, closing the window).
- **While the window is open**: completions defer at `on_renderer_finished`, the inline gapless swap stands down (`GaplessSwapOutcome::SkipFadePlanPending`), and `store_prepared_decoder` stores WITHOUT reset/arm (it must neither cancel the live blend nor arm against the advanced cursor; `finalize_crossfade_engine` re-arms from the slot). The controller's prep guard against a next song equal to the engine's source (it protects an engine AHEAD of the queue, after an inline gapless swap the completion has not caught up with) stands down while `skip_landing_pending()` (window open or skip blend live): the engine is BEHIND the queue then, and after Previous the song after the target is the outgoing itself.
- The `skip_fade` marker makes a skip-fade finalize suppress the completion callback (the queue advanced at skip time; `decide_transition` would advance it twice) and the `last_transition_was_crossfade` stamp; `recover_stalled_crossfade`'s skip-aware branch hard-loads the skip target instead of using the end-of-track machinery. The `Blocked`/failure fallback re-checks `immediate_playing()`: after a stop/pause during the build (neither bumps the generation) it stages the target as a `StageStart::Cue` (loaded, not played), so a later Play starts what the queue names.
- **Invariant: once a skip or click has advanced the queue cursor, every engine path ends with the engine on the track the queue names; only a new source change may override it.** A live skip blend's incoming IS the queue's current track: `reset_next_track` spares it (every queue mutation and mode toggle reaches it; the progressive append lands mid-blend on every large play); `seek`, `stop` and `set_source`'s internal stop end it through `end_crossfade_on_queue_track`, which promotes a skip blend (`finalize_crossfade_engine` at any progress, callback suppressed) and cancels an auto blend back to its outgoing (the cursor has not advanced); `plan_skip_fade` cancels it. `cancel_crossfade` alone always restores the OUTGOING, so a new early-exit path calls the helper, never a bare cancel.
- **Seek in the finalize gap**: the render thread finalizes its half first (incoming promoted, renderer no longer Active) and the engine half follows one task hop later in `on_renderer_finished`. A seek landing there finalizes the engine half itself (`finish_a_blend_the_renderer_ended`: `try_finalize_crossfade`'s verdict; an auto blend's completion callback fires there, once), bumps the source generation so the already-dispatched `on_renderer_finished` fails the renderer's staleness gate, and drops the seek (it was measured on the ended track's timeline). A seek that reopens checks again when its answer lands (`finish_seek`). However long the gap lasts (any engine-lock hold, a hard load's probe), the incoming's decode loop feeds the promoted stream: the renderer's `FinalizedBlend` record routes `write_crossfade_samples` to the primary and gives the loop's backpressure the primary's count (`incoming_buffer_count`), the loop writes each chunk before it lets the decoder go (the engine's finalize takes it under that lock, so nothing reorders), and `take_crossfade_elapsed_ms` hands the promoted track the fade's length plus what it played since. Read as an empty ring there, the loop once read the whole incoming stream into nothing during a slow reopen, and the promoted song ended where the blend's audio did (`a_blend_that_ends_during_a_slow_reopen_keeps_the_incoming_playing`). The outgoing's own loop is not routed: past the fade it is normally at its end already. `reset_next_track`, `stop` and `plan_skip_fade` still cancel in that gap (open, see local/TODO.md Loose ends).
- **Seek in the build window** (IPC `next` replies before the fire) is aimed at the target: `seek` records it as `deferred_skip_seek` under the plan's generation and leaves the outgoing untouched (no seek lost at the fire, no re-arm against the advanced cursor). Every `complete_skip_fade` exit that lands the target consumes it: after the fire `apply_deferred_skip_seek` promotes and seeks; a fallback load takes it via `take_deferred_skip_seek` as the staged start offset (armed between the load and `play()`). Both drop a record from another plan's generation.
- **Clock**: the public `position()` / `duration()` describe the track the queue names (their readers, the UI tick, MPRIS and queue push, pair them with the queue's current song): in the build window, duration 0 and position 0 (or the window's deferred seek, where the target will start); in a skip blend, duration 0 and the renderer's `crossfade_played_ms` (the incoming's pause-corrected played time, counting on through the render-thread-finalized gap by the promoted stream's own clock; finalize hands it to the promoted track). A 0 duration makes the UI fall back to the song's metadata length. Engine-internal decisions about the audible stream (the fire's remaining-audio clamp, end-of-track detection) read the private `stream_position()`.
- **Clicks** (queue click, play-from-here, browse-view play, all funnelled through `PlaybackController::load_play_and_set_current`) use the same three phases via `plan_click_play` (M10), the click's own queue sequencing replacing the navigator's. Clicks, Next and Previous share one route decision, `skip_transition(mode)` → `SkipTransition::{Crossfade, BoundaryFade, Cut}` (engine): Crossfade needs M7 viability (`skip_crossfade_viable()`) and no ACTIVE bit-perfect Strict, read from the same renderer `enforced_bit_perfect_mode()` that `crossfade_blocked` enforces, so Strict skips and clicks cut at once (no decoder build the fire would throw away) and a no-op Strict on the cpal fallback blends; BoundaryFade needs the same viability and runs `run_skip_out_fade` before the hard load; everything else (mode Off, paused, stopped, a radio outgoing) cuts.

**Content-aware overlap** (all opt-in, default off/0). *Leading trim* ("Skip Silence Between Tracks"): a decoder-side pre-roll scan on PREPARED transition decoders (`LeadingTrim` in `decoder.rs`) drops frame-aligned leading audio below `SOURCE_SILENCE_THRESHOLD` (`audio::mod`, 1e-3 ≈ −60 dBFS peak — one shared constant so the two halves can't disagree) up to a 15 s budget; any decoder `seek()` ends the scan; the scan lives inside the registry-backed decode path. *Trailing trigger*: a lazily-enabled per-stream level meter (`StreamHandle::{level_meter_enabled, recent_source_peak}` — real samples only, so ring starvation can never fake musical silence; seeded loud) lets `tick_trailing_silence` fire the armed blend early after 500 ms of sustained sub-threshold level, only inside a 15 s window before the trigger point (a mid-song quiet passage can never fire). Both halves stand down under bit-perfect modes. *Gap/overlap offset* (`crossfade_offset_secs`, −2…+2 s): negative mirrors to `renderer.crossfade_lead_ms` so the Armed position trigger fires |offset| early; positive rides `transition_prep_cfg()` → per-transition `gap_offset_ms` → the decode loop's EOF silence injection (`inject_transition_gap` — one-shot `swap(0)`, stands down when a blend or an open skip-fade window owns the transition; album-continuity joins zero it controller-side). *Bar-snap* ("Snap Crossfade to Musical Bars"): the controller snaps the fade to whole 4/4 bars of the outgoing's `Song.bpm` (`crossfade_policy::bar_snapped_crossfade_ms`, pure; `Some(0)` BPM guarded), clamped ±1 bar within the 1–12 s slider bounds, and threads it down as `duration_override_ms`. The override follows the M4 suppress-flag lifecycle exactly and is mirrored into `crossfade_duration_shared` in lockstep — the decode cushion must always cover the duration that actually plays.

**Stall watchdog**: `tick_crossfade`'s completion gate at `progress ≥ 1.0` is empty-ring **OR** liveness-stalled. `crossfade_liveness::IncomingLiveness` is a per-fade handle the crossfade decode loop brackets around ONLY its blocking decode/network call (backpressure sleeps, EOF exits, and lock handoffs stay outside the bracket and always read live); one read continuously in flight ≥ `CROSSFADE_STALL_READ_MS` (3 s) counts as stalled, and every race degrades toward "live" (= promote, the pre-watchdog behavior). Never use a count-based discriminator — `crossfade_buffer_count` grows and shrinks for healthy reasons. Recovery routes through the existing `IncomingStalled → on_renderer_crossfade_stalled → recover_stalled_crossfade` path (gated on `is_crossfade_live`, the 2c645885 livelock guard) and signals exactly once per fade (`stall_recovery_signalled` latch, cleared with the fade at start/cancel/finalize).

## Visualizer Sync

Samples reach the FFT thread pre-volume (CLAUDE.md; pipeline in visualizer.md). `is_dirty()` gates redraws, so the GPU idles while paused. Toggling the visualizer **off** also releases CPU: a `viz_enabled` atomic (renderer → `RodioOutput` → `StreamingSource`, ANDed with `feeds_visualizer`) skips the per-sample tap, and a synchronous `feed_active` flag early-returns the 60 Hz FFT worker. Both follow ONE predicate, `Nokkvi::visualizer_feed_wanted()` (a visualizer mode other than Off, OR the Harbour Trawl scene on screen, whose night light follows the music): the tap gate is pushed on cycle, settings load and the Harbour scene's on-screen edge (`sync_visualizer_feed`), the worker gate by `Nokkvi::sync_visualizer_mode` (cycle, settings load, login, the same edge), so a persisted "off" never spins the worker off Harbour. Only the active primary feeds the shared callback (`StreamHandle.feeds_visualizer: Arc<AtomicBool>`: `true` from construction for primary streams, init / seek-recreate; `false` for the crossfade incoming); otherwise two concurrent streams at different rates tag batches with their own rate, flipping the visualizer's stored-rate atomic every batch and thrashing the spectrum engine into constant reinit (blank bars in cross-rate crossfades). `tick_crossfade` hands the feed to the incoming at the fade midpoint (`progress >= 0.5`, where every curve's gains cross, so the handoff is curve-independent), so the viz never freezes when the outgoing EOFs and its ring drains in the crossfade tail; `finalize_crossfade` reaffirms `true` on the promoted primary and `cancel_crossfade` restores it on the restored outgoing (a cancel after the midpoint handoff would otherwise freeze the spectrum until the next track). The same callback feeds the MilkDrop analyzer: in MilkDrop mode the FFT worker's `tick()` hands it the buffered samples instead of the spectrum engine (see visualizer.md "MilkDrop Mode").
