# Artists View: Biography & Similar Artists

## Artist Biography (Artists)

Navidrome fetches an artist's biography and link from its agents only when a client calls `getArtistInfo2`, so the Artists view asks about the centred artist. The centred artist is `Nokkvi::centred_artist_id()`: the effective centre (a clicked row's highlight first, as the pill resolves it), with an expanded artist's album row resolving to that artist. Every centring path (the `LoadLargeArtwork` arm, `ExpandArtist`, the post-load centre in `ArtistsTarget`, `prefetch_viewport_artwork` outside a roulette spin) goes through `Nokkvi::artist_center_tasks` (large art + a 300 ms settle timer), the `LoadLargeArtwork` arm through its navigation twin `artist_step_tasks`, whose large art goes through the big panel's gate (gotchas/artwork.md); Harbour's artist rows fetch only the art. The timer's `InfoSettled` asks only if no other artist was centred since (`ArtistInfoState::centre` / `settled`), because a first ask makes the server run its agents and broadcast refreshes, too much for every row a held arrow key passes. Answers live on `Nokkvi.artist_info` (`ArtistInfoState = CentredFetch<ArtistInfo>`, `src/state/centred_fetch.rs`): a `SnapshottedLru` keyed by artist id, an in-flight set, and a session `StaleDropGen` carried forward by `reset_for_session`. One ask per id while it is cached; a failure is logged, never toasted, and asked again on the next centring; an answer that lands after the user moved on is kept under its own id. The same timer also asks for the centred artist's **similar artists** (`AppService::similar_artists`) into `Nokkvi.artist_recs` (`ArtistRecsState`, `src/state/artist_recs.rs`: a `CentredFetch<Vec<ArtistRec>>` plus the one artist waiting on its MusicBrainz id). Two sources feed it, each its own General setting, read together as `Nokkvi::rec_sources()` (`RecSources`): ListenBrainz (Similar Artists: ListenBrainz, default on) by MusicBrainz id, Deezer (Similar Artists: Deezer, default on) by the artist's own name (`Nokkvi::artist_name`: the library row's; without one the backend reads it by id, `AppService::own_artist_name`, because a song or album row names its artist by the track's display text, "A feat. B", which Deezer's exact match never finds). Everything that gated on the setting gates on `rec_sources().any()`. `artist_recs_task` takes ListenBrainz's id from the native row's `mbz_artist_id` or the fetched info's; with ListenBrainz on and the info still out it waits (`wait_for_mbid`), even when Deezer could go by name at once, and `handle_artist_info_loaded` resumes it (with Deezer on also after a failed info fetch); with no id for ListenBrainz and Deezer off it settles on an empty list. A change of sources (`rec_sources_changed`, from `handle_player_settings_loaded`; a hot reload that re-delivers the same pair does nothing) resets the cache like a logout and asks again for the centred artist and the open modal's (`reask_artist_recs`); a library toggle and a wildcard library change (a scan) do the same, since every row carries its "in library" standing. Each row's `RecSource` says who listed it (ListenBrainz by MBID, Deezer by Deezer id, or both); the list arrives with the artists the library lacks first, and within each group the ones both services name first. The pill lists them under the bio (`similar_artists_block`): under a "SIMILAR ARTISTS" header between hairlines in the accent at `SIMILAR_RULE_ALPHA` (the theme's `border()` is a dark groove on the artwork panel and vanishes there), a tag for an artist the library has is a filled accent tag (`accent_fill` + `on_accent_fill`, on the `mouse_area(HoverOverlay)` chassis with `on_accent_surface`) and bubbles `ArtistsAction::NavigateAndExpandArtist` (pane-aware through `handle_common_view_action`); one the library has only on other artists' albums (`LibraryArtist::album_artist == false`, from the native row's per-role `stats`) goes to Songs filtered by that artist, since the Artists list has no row to expand for them; one the library lacks is an outlined tag (`fg4` edge, `fg3` ink) with a globe and opens the artist's page on the service that listed them (`ArtistRec::page_url`: ListenBrainz's when it listed them, else Deezer's; `similar_artist_message`). The same list is reachable from a queue row's menu as the **Similar Artists** modal (`ActiveModal::SimilarArtists`, `widgets/similar_artists_modal.rs`, handler `update/similar_artists_modal.rs`): a picker-shell list on `Nokkvi.similar_artists_modal`, opened by `open_similar_artists_modal(artist_id, name)` (`QueueAction::SimilarArtists`), which asks for the info and the list when the cache has none and is filled by `sync_similar_artists_modal` when they land; Enter or a row press routes like the chips and closes it for a library artist, the row's globe (`OpenArtistPage`) opens the listing service's page either way. `NoMbid` shows only with Deezer off; with it on an empty list reads as none found. Every album, song and artist row menu offers it too (`LibraryContextEntry::SimilarArtists`): each view hands the row's `ArtistRef` (an artist row is itself, an album or song row its artist; an id the server left out stays empty and the open toasts `NO_ARTIST_TOAST`) up as `CommonViewAction::SimilarArtists`, which `handle_common_view_action` turns into `SimilarArtistsModalMessage::Open`; the Similar tab's `SimilarAction` opens it directly. Shift+R (`HotkeyAction::SimilarArtists`, Theater `ExitOnly`) opens it for `focused_artist()` (the focused-row record's `artist_id`, plus Harbour's artist and song items; album items carry only an album id) and closes it again, the key gate admitting it while the modal is on top. The chips' hover note is `similar_artist_note`, the modal row's words: MusicBrainz's comment, the library standing, then the listing service (`RecSource::label`). The pill (`pill_bio_and_link`) takes the native row's biography and link field by field and falls back to the fetched answer (a filled native row is never the older of the two), offers only an http(s) link (it goes to `xdg-open`), and labels it with its host (`bio_link_label`), because the link comes from whichever agent answered. Navidrome announces every info fill with a `refreshResource` broadcast that reaches every client, nokkvi included: a first ask broadcasts twice (the synchronous fill, then the background refresh it queues about 5 s later, since an artist with no info counts as expired), and so does any ask past the 24 h time-to-live. Each broadcast reloads the Artists list in the background (skipped under Random sort, while the list is empty, or past `MAX_RELOAD_ROWS`).
