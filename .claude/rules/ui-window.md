# Window-Level Surfaces (Modals, Theater, Artwork Bleed, Tray)

## Modals

**One registry for the root overlays** (`update/modals.rs`): `ActiveModal` names the eight root modals and `ActiveModal::STACK` lists them top to bottom (text-input dialog, EQ, About, Info, Similar Artists, default-playlist picker, MilkDrop picker, Trawl: the smaller, more transient surface sits higher; pinned by `stack_order_is_pinned`). `Nokkvi::top_modal()` is the open one highest in STACK, and every site matches on it exhaustively: the draw order (`wrap_with_global_overlays` walks STACK bottom-up through `modal_overlay`, one fixed `Stack` layer per modal with a placeholder while closed, so a modal opening under an open one never shifts it and drops its focus), the key gate in `handle_raw_key_event` (only Escape plus the keys `ActiveModal::takes_action` gives the top modal pass: list keys (the bare arrows among them) for the pickers, those plus Ctrl+Enter, `/` and `TRAWL_TRAY_ACTIONS` for Trawl, its own toggle key for EQ / Get Info, and the media keys (`MEDIA_KEY_ACTIONS`) for every modal), Escape (`handle_clear_search` closes the top modal first, one per press, through `close_modal` = that modal's own Close message, with the Escape SFX; ahead of a roulette spin), the slot-list routing (`handle_modal_list_key`; the scrollbar-fade and seek-settled timers always reach the view), and logout (`discard_modal` for every STACK entry; never Close, whose side effects are wrong there). A new root modal goes into the enum, STACK and the pin, then each site's compile error. View-hosted sub-pickers (settings font/theme pickers, the rules-editor pickers) are not root modals.

- **Equalizer**: 10-band + presets (`widgets/eq_modal.rs`, `update/eq_modal.rs`). Selecting a preset auto-enables the EQ. Sliders visually reset to 0 dB when disabled.
- **About**: metadata/diagnostics, theme-adaptive logo (`widgets/about_modal.rs`, `update/about_modal.rs`). Includes a Ko-fi tip link. The Commit row hides gracefully when built outside a git context.
- **Info**: Get Info two-column property table (`widgets/info_modal.rs`, `update/info_modal.rs`). `InfoModalItem` variants per type.
- **Text Input**: name/comment edits + confirmations (`widgets/text_input_dialog.rs`).
- **Trawl (mix builder)**: whole-library seed search over the persistent `TrawlCrate` on `Nokkvi.trawl.mix` (`widgets/trawl_modal.rs`, `update/trawl_modal.rs`, `state/trawl.rs`). Modal state on `Nokkvi.trawl.modal`; opened by `t` (never over Settings), the Harbour door or the Queue header; menus' "Add to Mix" only adds seeds. Rows derive from ONE builder (`build_trawl_rows`) for render/activation parity; every surface that adds seeds (search rows, library/queue/Similar menus) builds them with `TrawlSeed::from_{song,album,artist,genre,playlist}`, which own each kind's chip label; search stale-drop generation lives beside the modal, not in it (`trawl.search_generation`), so close/reopen can't re-mint captured generations. Enter toggles the centered seed; Ctrl+Enter maps to Play Mix in its slot-list intercept. Shift+Tab / Shift+Backspace step `TrawlModalState.tray_cursor` around a ring of None + `TrawlTrayControl::ALL` and the horizontal arrows — BOTH the bare seek pair and the Shift sort pair — cycle the focused control's value through its const `ALL` array via the existing `Set*` write path; `/` and typing clear the ring. INVARIANT: the trawl branch sits FIRST in `handle_settings_category_motion`, and in `Nokkvi::horizontal_arrow_context` (`update/hotkeys/navigation.rs`), which BOTH `handle_cycle_sort_mode` and `handle_seek_step` call as their first statement — above the SFX play and `reveal_current_toolbar()` — or the obscured background view gets stray SFX and a stranded toolbar reveal-lock; the key gate admits them only for Trawl, through `TRAWL_TRAY_ACTIONS` (`update/modals.rs`: the sort and seek pairs both), the one list the Trawl arm of `ActiveModal::takes_action`, the gate's Captured double-handle check and the IPC `key_gate_instead` all read; `trawl_verbs_follow_the_key_gate` holds the IPC verbs to the key gate.
- **Default Playlist Picker**: modal sub-slot-list to choose the default playlist (`widgets/default_playlist_picker.rs`, `update/default_playlist_picker.rs`). Like the MilkDrop picker it runs on the shared `widgets/picker_modal.rs` shell (list state + chrome; see widgets.md), so a search keeps the centered entry when it still matches in both. State on `Nokkvi.default_playlist_picker`; opened from the chip in the Playlists/Queue header or the Playback → Default Playlist settings entry.
- **MilkDrop Preset Picker**: searchable list of every preset (`widgets/milkdrop_picker.rs`, `update/milkdrop_picker.rs`). State on `Nokkvi.milkdrop.picker`; opened by Choose Preset (`m`, Theater Passthrough) or the MilkDrop panel-menu row, only in MilkDrop mode. Sits right under the default-playlist picker in `ActiveModal::STACK`; the key gate's `MilkdropPicker` arm also takes raw ArrowUp/ArrowDown for it. The centered row previews live, Enter / a row click chooses AND locks, any other close restores the preset and lock from open. Heart / eye / Favorites-chip clicks refocus the search field.
- **Font / Theme pickers** (settings sub-lists): centered modal overlays over the settings panel — see settings-view.md for picker internals.

Every root modal goes through `theme::modal_scaffold`: a backdrop `mouse_area` whose press closes it, wrapped in `opaque()` so pointer events never reach the view behind.

## Theater Mode

A now-playing layout (`update/theater.rs`, state `src/state/theater.rs`, `Message::Theater(TheaterMessage)`): the window shows only the playing subject's panel (cover, over-cover visualizer, lyrics) and the player bar slides in over it. Transient: never persisted, never entered on Login.

- **Single entry point**: F11 (`HotkeyAction::ToggleTheater`), the Queue cover's hover-revealed corner icon and its "Enter Theater Mode" menu row (`QueueAction::EnterTheater`), and the `theater` IPC verb all call `Nokkvi::enter_theater` / `toggle_theater`. Entering and leaving are unmount edges (see gotchas/view-tree.md).
- **Key policy**: `theater_key_policy(HotkeyAction)` is an exhaustive match: Passthrough (transport, modes, seek, lyrics, visualizer, the toggle, Escape), ExitThenPerform (view switches, `/`, Ctrl+E, Shift+C, Trawl, Roulette, refresh, save-queue, Find Similar / Top Songs, which act on the PLAYING track), ExitOnly (anything aimed at the hidden centred row or a hidden Settings row). `theater_key_policy_here` refines it: a toggle whose hidden target is already on (backtick over Settings, Ctrl+E with the split view open) only leaves. Wiring in `handle_raw_key_event`: the rules-editor intercept stands down while active; after the modal gate and only with no modal open (`top_modal()` is `None`), a Captured Escape is swallowed (it belongs to the overlay menu that captured it) and the policy applies; ExitThenPerform RE-RUNS the raw key after the exit, never `self.update(msg)`. `horizontal_arrow_owner()` returns `View` in theater, so bare arrows seek even over Settings. Escape's exit sits in `handle_clear_search` after the modal tier (and after a roulette spin and a cross-pane drag). A held toggle key's repeats are dropped (`RawKeyEvent` carries winit's repeat flag). The IPC list verbs (`nav-up`, `nav-down`, `enter`, `add-to-queue`, `remove-from-queue`) take the same gate through their keys' twins (`key_gate_instead` in `update/ipc.rs`): under a modal, in theater or not, the verb does what its key would there (the queue pair does nothing, except Shift+A's Trawl mix) and theater stays; with no modal on top, ExitOnly leaves theater, the verb does not act, and its reply adds `"theater":"exited"`. `clear-queue` stays out on purpose (it clears the whole queue and aims at no hidden row).
- **Mouse-route safety net**: `handle_switch_view` exits first, and the root `update` exits whenever a message changes `theater_route_snapshot()` (view, browsing tab, editor presence). Find Similar / Top Songs exit explicitly (a re-run on an open Similar tab changes no route).
- **Widened gates**: `lyrics_surface_visible()` (Queue view OR theater) gates every lyrics resolve / next-track prefetch / backdrop blur; `theater_large_art_task` loads the playing song's large art (its cover key, gotchas/artwork.md) on entry and on song change.
- **Layout**: `theater_view` is a FIXED four-layer `Stack` (panel, two `bottom_band_layers` placeholders-or-real, chrome), so the bar's slider/marquee state survives `v`. The chrome (corner exit icon + the unchanged player bar) is translated by `OverflowPin`, never resized. The chrome flips only in `theater::tick` (per frame, from the frame tick): `chrome_target` (Theater Controls; auto-hide = focused && (bar/corner hovered || menu open || activity within `HIDE_DELAY`)), eased by `slide_offset`. `cursor_hidden` is its own rule. Activity comes from a subscription present only while active, plus the key stamp.
- **Content**: `theater_now_playing_cover` (station art for radio; the playing song's cover, frosted only while the lyrics layer shows). The lyric sheet is the Queue's (`queue_lyrics_panel_data`); the viewport sizes its text from the panel (`panel_fit_scale`, 1x..2.5x by the shorter side) on both surfaces, so one panel size shows one text size. Cover Art hidden in theater paints `cover_backdrop()` and forces `PanelShape::Fill`.
- **Window**: Theater Fills the Screen queries the mode on entry; `PriorModeKnown` stores it and requests fullscreen only while still active on the same window; exit restores and consumes it. Close-to-tray (both paths) and quit-by-close use `exit_theater_for_closing_window` (drop, never restore); logout / session expiry exit via `reset_session_state`.

## Artwork Bleed (Lowered Player Bar)

When the current view renders its artwork column beside the list (Horizontal; never in split-view or Theater Mode), `home_view` lowers the player bar: `Nokkvi::lowered_player_bar_width` resolves the list's width from the same config the view builds (`horizontal_artwork_side_width` mirrors the render, for a column the window's full height), and `dock_chrome` stacks the top chrome (the top nav bar and/or the Metadata Strip row) and the player bar over `main_content` at that width, so the artwork runs the window's full height beside them in every nav layout and strip mode. The view leaves room through `ArtworkBleed` (`Nokkvi::artwork_bleed` → `*ViewData.bleed` → `BaseSlotListLayoutConfig.bleed`): `top` is the band the list keeps empty for the docked top chrome (`slot_list::top_chrome_height()`), `bottom` pins the list column's width and ends it with a `player_bar_height()` band. `chrome_height_with_header` is built on the same `top_chrome_height()` plus the bar, so the list keeps its rows. Every nav layout docks through `dock_chrome`, whose widget-tree shape is the same lowered or not, so the nav's, the strip's and the bar's state survive a flip. The lowered nav and bar lay out against their own width (the nav's tab and metadata breakpoints, the bar's mode culling and width gates), and the chrome riding on the bar shares its x-range, `Nokkvi::bottom_chrome_span` (clear of the sidebar; beside the artwork column only as wide as the lowered bar): `toast_insets` derives from it, and the bottom-band visualizer and its boat (`bottom_band_layers`, the boat's wrap margin in `update/boat.rs`) draw across it, so neither crosses the artwork column. Probe configs and split-view pass `ArtworkBleed::NONE`.

## System Tray

`src/services/tray.rs` runs a ksni-based StatusNotifierItem on a dedicated thread. `update/tray.rs` handles `TrayEvent` (toggle window, play/pause, next/prev, quit) and window-close-to-tray when `close_to_tray` is enabled. Every "bring the window back" caller goes through `Nokkvi::show_window` (same file), which returns a `ShowOutcome`: `AlreadyOpen` when `main_window_id` is set (flags the window with `request_user_attention`), `Opened` when it was closed to the tray (reopens via `set_window_hidden(false)`), and `Opening` when neither holds because a window is already on its way (boot gap, or a second show before `WindowOpened`), which does nothing. The `show` IPC verb echoes it as `{"window":"already-open"|"opened"|"opening"}`.
