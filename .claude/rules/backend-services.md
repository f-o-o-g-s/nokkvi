# Backend Services

## Service Architecture

`AppService` orchestrates: `PlaybackController` (audio engine + queue navigator; `reset_next_track()` on mode toggles) plus the composed backend services (AuthGateway, Albums/Artists/Songs/Queue/Settings). Albums/Artists/Songs share the `LazyAuthedService<A>` newtype (`backend/lazy_authed_service.rs`) for their `tokio::OnceCell` + constructor-closure lazy-init pattern.

- **Orchestrator borrow-handles** (built per-call from `app.queue_orchestrator()` / `app.library_orchestrator()`, not stored on AppService):
  - `QueueOrchestrator` — queue-mutation verbs (`enqueue`, `enqueue_and_play`, `insert_at`, `play_next`, `play`), plus the `QueueVerb` / `StartPosition` enums consumed by the private `AppService::dispatch(SongSource, QueueVerb)`. Every public `play_*` / `add_*` / `insert_*` / `play_next_*` entity-verb wrapper on AppService delegates to `dispatch`, or to `dispatch_shuffled` when it takes a `OneShotShuffle` (a one-shot permutation that never sets the persistent shuffle mode); the `*_from_track` wrappers pin the clicked track via `dispatch_anchor_first_from_track`. `dispatch` resolves the source, applies the single empty guard (`SongSource::empty_error_message()`, entity-named + toast-surfaced), then hands the songs to the matching orchestrator verb. Add new entity-verb combinations as wrappers over these — never as hand-rolled resolve+guard+verb bodies. (`add_song_to_queue_by_id` is the one special case: find-in-album + custom error, then `queue_orchestrator().enqueue`)
  - `LibraryOrchestrator` — entity resolution unified behind `resolve(SongSource)`; `resolve_trawl(&TrawlCrate)` resolves + blends a Trawl mix crate's seeds. In `resolve_batch` and `resolve_trawl` an item the server fails is skipped (counted into one `warn!` per batch), but a rejected session (`NokkviError::is_unauthorized`) ends the whole resolution with that error, so the UI drops to login instead of toasting "No songs found"
- **On-demand API services** (no backend wrapper) — generated by paired `native_api_factory!` + `subsonic_api_factory!` macros in the API-factory block of `app_service.rs` (the Subsonic factory adds `server_url` + `subsonic_credential` from `AuthGateway::server_config()`). All native construction (the macro, the ad-hoc `SongsApiService` sites, `LibraryOrchestrator::resolve_genre`) funnels through `AuthGateway::build_native_api(factory)` — one auth dance, one "Not authenticated" error. `LazyAuthedService::build_authed(factory)` layers it for ad-hoc (uncached) construction from a wrapped gateway. The one exception is the gateway's own API-key setup, which builds `PlayersApiService` from the client in its one-lock session snapshot
- **OpenSubsonic API keys** (`services/api_key.rs`; `AuthGateway::establish_api_key` / `revoke_api_key`; native `services/api/players.rs`): when `getOpenSubsonicExtensions` lists `apiKeyAuthentication`, every password login mints a fresh `nds_` key (`ApiKey::mint`, OS random source), puts it on nokkvi's player with a key-only `PUT /api/player/{id}` (one player per install and session owner; its id and user id kept in redb under `api_key_players`), confirms it with `tokenInfo`, then swaps the session's `/rest` credential to `apiKey=<key>`. A 404 there makes a new player with `POST /api/player`, named `nokkvi (<hostname>)` and seeded from the player Navidrome registered for nokkvi's token requests (`nokkvi [<user agent>]`; `scrobbleEnabled` is always sent, because an omitted field is Go's zero value); a 403, an unreadable player list or player records, or a JWT whose `sub` isn't (or can't be read as) the session's user fails the setup before anything is written, and a player it can't record fails it after. A resumed token session upgrades in the tracked `api_key_upgrade` task and saves only the credential (`save_subsonic_credential`, never rolling back the JWT); a resumed keyed session on a server whose extension list lacks the key extension ends (`extensions_fetched_message`). An explicit logout revokes the key (key-only PUT, empty value) after reading the player (a revoke is owner-or-admin, so another user's row is never touched), on a client that never persists a refreshed JWT, under the process-wide key-write lock claimed synchronously in `handle_settings_logout` and bounded by `KEY_REVOKE_BUDGET`; a failure toasts, and so does a keyed session whose player has no record. A session that expires keeps its key until the next login replaces it. Every other failure, and a server without the extension, keeps the token pair; only a login whose server sent no token pair and could not get a key fails
- **Multi-library selection** — `active_library_ids: Arc<RwLock<HashSet<i32>>>` + `all_libraries: Arc<RwLock<Vec<Library>>>`. Empty selection = "no filter" (all libraries). Persisted to redb under `ACTIVE_LIBRARY_IDS_KEY`; mutators: `toggle_library`, `refresh_libraries` (server fetch, then `apply_library_refresh` prunes + persists). The songs/albums/artists loaders take the scope inside the shared `LibraryQuery` (`types/library_query.rs`: one sort/search/filter/library shape, so the same-typed `&str` sort args can't swap); genres/playlists take `library_ids` on their `_with_libraries` loaders
- **Artwork** — server-only, no client-side persistent cache. `AlbumsService::artwork_client: Arc<reqwest::Client>` (bare reqwest); concurrent in-flight fetches capped at 16 via a `Semaphore`. `fetch_artwork_by_url_with_retry` is the single shared retry impl (3 attempts, 100/200 ms backoff) sitting in front of Navidrome's `getCoverArt` throttle. Empty-bytes responses surface as errors so retries can recover instead of caching a blank handle
- **SSE** — `data/src/services/navidrome_events.rs::parse_sse_event` parses events; the subscription itself runs in the UI crate (`src/services/navidrome_sse.rs`) and dispatches `Message::LibraryChanged(LibraryChange { album_ids, artist_ids, song_ids, playlist_ids, genre_ids, is_wildcard })` → ID-anchored slot-list reload handled by `update/library_refresh.rs`. `handle_library_changed` returns early off the Home screen: a star, rating or scrobble confirmed after logout replays its refresh (below) with nothing to reload or announce. Each entity branch reloads only when its ID list is non-empty (or the payload is a wildcard); wildcard events also re-fetch the multi-library list. The event itself refreshes no artwork (a blanket refresh flickered on every play-count bump); covers follow the reload's version-gated prefetch (gotchas/artwork.md "SSE refreshes covers only through the reload"). The user-initiated right-click "Refresh Artwork" forces a refetch. **Own writes don't echo**: every native request, every event-causing `/rest` request (`subsonic_post`, the scrobble GETs in `services/api/scrobble.rs`) and the SSE connection carry `X-ND-Client-Unique-Id` through `client::with_client_unique_id`, so the `refreshResource` nokkvi's star / setRating / scrobble causes skips nokkvi's stream and reaches only the same user's other sessions (untagged, it went to every user on the server). The UI replays it once the write is confirmed: `star_result_message` / `rating_result_message` (and love's 5-star write) send `LibraryChange::for_annotation`, `handle_scrobble_submission_result` runs `ScrobbledSong::library_change()` (song + album + artist). A new event-causing write follows the same pattern.
- **Waveform envelopes** (`services/waveform/`, `AppService::cached_waveform` / `scan_waveform` / `next_song_id_in_play_order`): Navidrome serves no peaks, so the Waveform seek bar style's envelope is worked out once per song and kept under `~/.cache/nokkvi/waveforms/<server hash>/` (one ~2 KB file per song, keyed by an md5 of its id, validated against the song's size + duration + suffix so a replaced file rescans; temp + rename writes; pruned LRU-by-mtime past 64 MB once per session by a tracked task). A scan requests the EXACT playback stream URL (`StreamSession::stream_url`): raw by default, and the same transcode playback gets when nokkvi's player has a server-side transcoding, so the envelope matches what is heard; with Navidrome's transcode cache on (its default) it also reads playback's cache entry, in progress or finished, and starts no second ffmpeg run. It opens the stream with playback's own `AudioDecoder` (`init` async, the read loop on `spawn_blocking`, both in a `waveform_scan` span) and folds buffers into `WaveformBuilder` without holding the PCM. Nothing is cached when it is cancelled (the UI's per-scan `TaskManager::child_token`, which logout's shutdown also fires), when it ends more than max(2 %, 2 s) short of the expected length (a dropped connection reads as a clean EOF), or when it runs slower than 4x realtime (the link delivering under four times the stream's bitrate) after a 3 s grace, which also turns scanning off for the rest of the session so a slow link never trades playback's buffering for a waveform. A failed cache write is logged and the envelope still reaches the bar; each writer uses its own temp file name. The UI side (`update/waveform.rs`, `state::WaveformState`) is level-set from the 100 ms tick: one job at a time, numbered so a late result from a dropped job never clears a newer one; the playing song first (cache, then a scan once 3 s in), then the next song in play order (asked again every `WAVEFORM_NEXT_REFRESH`, since a Play Next or reorder moves it), whose envelope waits in `ready` and shows the moment it starts. A song that left the queue (`WaveformLookup::NotInQueue` / `ScanEnd::NotInQueue`) or whose scan failed is given up for that play, so nothing is re-planned every tick.
- **TaskManager** — real supervisor over a `tokio_util` `TaskTracker` (tokio-util's `rt` feature), which counts each task before `spawn` / `spawn_result` returns, so a shutdown right after a spawn still waits for it. All spawn variants share one `spawn_tracked` body; they differ only in how the task meets the token and maps its outcome to a `TaskStatus`. `shutdown_all(budget)` fires the shared cancellation token (every task is `select!`-wrapped, so it ends at its next await), closes the tracker, waits up to the budget, then stops waiting. Nothing is aborted: a task still running then is stuck in synchronous code, which neither the token nor an abort can reach. `request_shutdown()` on AppService and the logout teardown both wait `TASK_DRAIN_BUDGET` (500 ms, `task_manager.rs`). Status channel still streams `TaskStatus` to the UI for notifications. UI-side subscription wrappers in `src/services/subscription_slot.rs` route the loop / queue-changed / task-status receivers through a shared `SubscriptionSlot<T>` (Notify-backed wakeup) instead of byte-identical 100 ms polling wrappers.

Cross-entity helpers in `backend/mod.rs`: `Starable` / `Ratable` / `PlayCountable` traits with shared list-mutation helpers and `flatten_participants()`.

`AuthGateway::server_config() -> (String, String)` returns the `(server_url, subsonic_credential)` pair under a single lock acquisition. Use this everywhere both halves are needed; never call `get_server_url()` + `get_subsonic_credential()` back-to-back.

`services/api/subsonic.rs` owns the shared Subsonic plumbing, including `deserialize_one_or_many` (single-object-vs-array quirk). Keep default serde on all wire structs (no `deny_unknown_fields`) — additive Navidrome fields must stay no-ops.

## Queue System

`SongPool` (HashMap) + `Queue` ordering (`rows: Vec<QueueRow{song_id, entry_id}>` + `order: PlayOrder` + `current_order`). Modules: `services/queue/{mod, navigation, order, write_guard}.rs`. The typed model:

- **`QueueRow`** carries the song id plus the runtime-only per-row `entry_id` — one `Vec`, so rows and their ids cannot desync. `entry_id`s reseed `0..len` on every load and are handed out by the monotonic `QueueManager.next_entry_id` afterwards.
- **`PlayOrder`** (`types/queue.rs`) is a newtype over a PRIVATE `Vec<usize>`: every constructor/mutator preserves the permutation-of-`0..len` invariant (`identity`, `shuffle_anchored`, `remove_row`, `remove_rows`, `extend_rows`, `insert_rows`, `splice_from_play_sequence`). `remove_rows` is the O(n) batch twin of `remove_row` behind `QueueManager::remove_entries_by_ids`, which removes any number of rows under one write guard with ONE `commit_save_all` (proptest-pinned against the old row-at-a-time loop, which paid an fsync'd save per row). Reads go through `Deref<Target=[usize]>`; there is no `DerefMut`. The one unvalidated constructor is the bincode decode path — `reconcile_loaded_queue` validates/repairs on load before any consumer.
- **The physical playhead is DERIVED**: `Queue::current_index()` returns `order[current_order]`; there is no stored index field, so `order[current_order] != current_index` is unrepresentable. Move the playhead via `set_cursor_to_row(row)` / `rebuild_order_and_set_cursor(row)` / direct `current_order` writes to an order slot.
- **Wire format is frozen and byte-identical to the pre-redesign layout** (8 slots; slot #1 is song ids only, slot #2 is the derived index written for backward compat and discarded on decode — write-only). Locked by `queue_bincode_golden_bytes` (+ asymmetric-flags companion) and `pre_refactor_queue_blob_still_loads`; the GOLDEN constants were captured from the pre-refactor encoder and are NEVER regenerated — a diff there is a wire break to fix in code.

- **Mutation guard** (`write_guard.rs`): every queue write goes through `QueueWriteGuard`, which forces the caller to pick a commit mode at the end of the borrow — `commit_save_all` (full save), `commit_save_order` (order-only), or `commit_no_save` (in-memory only). Each `commit_*` method returns a `NextTrackResetEffect` so a future reorder path can't silently skip the engine's gapless-prep reset. Drop without committing is the intentional safety net: it still runs `clear_queued()`, so `?` propagation or a panic between `write()` and `commit_*` can't leave a buffered next song keyed to pre-mutation order. A commit hands back its effect even when the save fails, because the rows already changed in memory and every caller acts on the in-memory queue (the UI mirrors it). So a failed queue save never fails the mutation, and the mutators return the bare effect, never a `Result`; so do the `QueueService` wrappers and the AppService queue verbs that only mutate. The failure is logged through `services::queue::warn_if_unsaved`, as are the navigator's cursor saves, the controller's reposition saves and the song-field writers (rating, love, play count). `Result` stays where real I/O can fail: `QueueManager::new`, a prefs persist, a play. Tests can fail every write with `StateStorage::fail_writes_for_test`.
- **Navigation typestate** (`navigation.rs`): `peek_next_song()` returns a `PeekedQueue<'_>` guard whose only public consumer is `transition()`. The crate-internal `transition_to_queued_internal` is the actual mutator — no other call site can advance the queue without first peeking.
- **The saved queue belongs to one session** (`services/queue/slots.rs`): the live `queue_order` / `queue_songs` keys carry a `queue_owner` stamp (`QueueOwner`: the resolved server URL through `slots::server_key`, which also names the waveform cache's per-server directory, plus the username through `user_key`; never the user id, which a resumed JWT can lack). Both login paths call `AppService::claim_queue_for_session` after authenticating and before `LoginSuccess`: the same owner keeps the live queue; another owner parks it under `queue_slot` keys (with its "Playing From" record, which lives in the user settings) and moves the incoming owner's slot, or an empty queue, in, all in one `StateStorage::write_batch`; then `QueueManager::reload` + `resync_navigator_with_queue` + `set_active_playlist` follow. A pre-stamp queue is kept only when one of its sampled songs exists on the server (`SongsApiService::song_exists`); none found drops it, a failed lookup leaves it unstamped for the next login. A new piece of per-session saved state belongs in the slot.
- Shuffle off: identity order. Shuffle on: Fisher-Yates with the current song anchored at index 0.
- (queue index/transition gotchas: see gotchas/queue.md)
- Every queue mutator (via the `QueueWriteGuard` commits) returns `NextTrackResetEffect` (`types/next_track_reset.rs`); an operation that runs two mutators folds their effects with `.and()` and applies once. The `#[must_use]` discharge contract makes engine gapless-prep invalidation a compile-time obligation across every reorder path, closing the queue/engine desync window that a shuffle + crossfade reorder used to open. A mutator that can prove the next track unchanged narrows its effect with `only_if(false)`, which makes applying it a no-op: `add_songs` does so for an append behind the next song (no shuffle, cursor not on the last row), so a large play's page-by-page append keeps the prepared next track. `apply_to(&Mutex)` locks the engine internally; `apply_locked(&mut Engine)` is for callers already holding the engine lock (completion callback consume path, `play_next` / `play_previous`).
- Progressive build: everything already loaded in the songs `PagedBuffer` plays immediately; a recursive `ProgressiveQueueAppendPage` chain (`src/update/progressive_queue.rs`) fetches the rest at `library_page_size` per page (100/500/1000/5000, default 500).
- **Reshuffle on repeat wrap**: shuffle + repeat-playlist re-shuffles the order array when the queue wraps back to the start.
- **Server queue sync** (`play_queue_api`, OpenSubsonic index-based `savePlayQueueByIndex` / `getPlayQueueByIndex` — NOT the legacy `savePlayQueue`): `AppService::push_queue` uploads the local queue + playhead; `pull_queue` replaces the model with the server's and **CUES** it via `PlaybackController::cue_pulled_queue` (restore position without auto-playing — see audio-engine.md), never `play()`. Also reachable through the `queue-push` / `queue-pull` CLI verbs.

| **Config writer** | `src/config_writer.rs` (UI crate) | Typed `ConfigKey { AppScalar, Theme, ThemeArrayEntry }`. | **Credentials** | `data/src/credentials.rs` | `server_url` / `username` in `config.toml`; JWT + Subsonic credential + the session's `SessionOwner` (resolved server URL + username) in redb, written in one `write_batch`. The credential is the `/auth/login` token pair (`u=…&s=…&t=…`) or an OpenSubsonic API key (`apiKey=…`). A resume goes ahead only while config.toml still names the owner (`resume_identity`; config.toml without a pair resumes as the owner; an owner that is stored but unreadable never resumes). **No password on disk** — JWT auto-refreshes via `X-ND-Authorization`; expired JWT (48h default) drops to the login screen |
| **Lyrics store** (`~/.local/share/nokkvi/lyrics/`) — a **third XDG root** (data_dir, distinct from config + state) | `services/lyrics_source.rs` + `types/lyrics.rs` (index + Tier-1/2 matcher) + `utils/paths.rs::get_lyrics_dir` | `.lrc` corpus matched to tracks by internal tags. `build_index` tags every entry with a `LyricsOrigin` — `Cache` for the store ROOT's own `.cache/` child (where `cache_to_store()` writes LRCLIB downloads) and everything under it, `User` for all else — and keeps the two in separate tier maps, read via `find_user` / `find_cached`. **Tier-1 supremacy stays corpus-wide**: a strict key held by the OTHER origin ends a lookup at `None` rather than letting this origin's Tier-2 (which strips `(Live)`-style qualifiers) outrank an exact sheet the other origin owns. Resolve order (`resolve_from`, four lazy channels, winner reported as a `LyricsChannel`): the user's own files, the server's `getLyricsBySongId`, cached LRCLIB downloads, the LRCLIB network fetch. The server outranks both LRCLIB channels; only the last is gated on Online Fetch. Each channel returns a `LyricsLookup` (`Hit` / `Miss` / `Failed`: a timeout, a transport or server error, an LRCLIB status other than 404, a failed Subsonic envelope, an unreadable file; an indexed file deleted since boot is a `Miss`); with no hit, the chain is `Failed` if any channel it asked failed. `session_verdict` decides what is remembered: a hit, a miss only when the chain was complete, a failure never (the next play retries). Session verdicts live in `LyricsSessionCache` (`AppService::lyrics_cache()`), dropped **only** on a wildcard `LibraryChanged` — every song-scoped `refreshResource` is an annotation write (scrobble / star / rating) that cannot change lyrics, and dropping those ids would re-run the whole chain, LRCLIB request included, per keypress. Each drop bumps a generation that `put_if_current` checks, so a resolve already in flight can't write its stale verdict back |

## SettingsService & SettingsManager

`SettingsService` (`backend/settings.rs`) is a thin async wrapper around `SettingsManager` (`services/settings.rs`) that holds only the methods the UI calls on it: sort prefs, volume, EQ, hotkeys, playlist context and a handful of toggles the UI flips outside the Settings tabs. Settings-tab writes skip it: `update/settings.rs` locks `settings_manager()` and calls the `dispatch_*_tab_setting` functions from `settings_tables`, so a new setting needs no wrapper method. The pass-throughs it keeps are generated by file-private `delegate_setter!` / `delegate_getter!` macros; a method that needs a cast, multi-arg signature, or two-call-under-one-lock sequence is written inline.

`SettingsManager` owns `settings: UserSettings` (= `PersistedPlayerSettings` + `ViewPreferences` + `HotkeyConfig`) + `StateStorage` + a config.toml-only `visualizer: VisualizerConfig` (never written to redb). Loads `config.toml` → merges with redb → `UserSettings`; the UI-facing live union `LivePlayerSettings` is projected on demand via `get_player_settings()`. Per-field setters persist atomically. `reload_from_toml()` for hot-reload: a file that can't be read or parsed returns `Err` and changes nothing; otherwise `Ok` carries the sections that were present but malformed (`TomlSections::malformed`), which keep their current values. The UI's `settings_reload_message` (`update/config.rs`) toasts both. Only an ABSENT `[visualizer]` resets the visualizer to defaults. Applying `[settings]` (startup and hot-reload) ends in `PersistedPlayerSettings::validate()`, which clamps hand-edited numerics into the same shared `_MIN` / `_MAX` constants the setters and sliders use (same pattern as `VisualizerConfig::validate`).

`LivePlayerSettings` is the live in-memory union of every user-tunable knob. Both it and `PersistedPlayerSettings` are emitted from ONE `player_settings_schema!` field table in `data/src/types/settings.rs` — a field exists in both structs (or the declared one) from a single row; the divergences (persist-only and live-only fields, f64|f32 splits) are declared per row, and the golden-bytes tests pin the persisted wire (field order, serde attrs, default values). `crate::types::player_settings` re-exports the Live twin, and its per-domain submodules own the knob enums. `TomlSettings` is the on-disk shape of `[settings]`. Read the structs for the full set.

The per-view column flags live on one canonical `ViewColumns` struct (`data/src/types/view_columns.rs`) embedded as `view_columns` in all three settings structs — `#[serde(flatten)]` on `PersistedPlayerSettings` / `TomlSettings` keeps every `{view}_show_*` key flat on both wire formats (pinned by the `*_column_keys_stay_flat_*` tests), and its single hand-written `Default` is the source of truth for shipped column defaults (so `LivePlayerSettings::default()` carries real column defaults, not all-false). Field names inside `ViewColumns` are wire keys — renaming one requires a migration.

### `define_settings!` registration

Every setting backed by the Settings UI is registered via the `define_settings!` macro (`data/src/services/settings_tables/{general,interface,playback,visualizer,columns}.rs`; the macro itself lives in `data/src/types/setting_def.rs`). Each entry declares `key`, `value_type`, `setter`, and the copy closures `toml_apply` (TOML → persisted), `read` (persisted → live) and `write` (live → TOML); the compiler rejects a missing one. `on_dispatch` and `ui_meta` (label / category / subtitle / default) are optional. `setting_def.rs`'s module docs list what the macro emits. Use `SettingsSideEffect` (`data/src/types/settings_side_effect.rs`) variants to thread side effects (toasts, atomic flag flips, library reloads) back to the UI from `on_dispatch`. Hotkey actions follow the same single-table pattern via `define_hotkey_actions!` in `data/src/types/hotkey_config/action.rs`.

Adjacent enum macros: `define_labeled_enum!` (`data/src/types/labeled_enum.rs`; its `LABELS` const is the Settings row's options, see settings-view.md "Enum rows take") for label/wire-string-backed enums (most `player_settings` knobs; `QueueSortMode` keeps its own `TABLE`, `VisualizationMode` is plain serde, and the visualizer-config enums use `wire_enum!`, see visualizer.md); `atomic_u8_enum!` (`src/atomic_u8_enum.rs`) for the enum-typed `UiModeFlags` atomics (`theme/ui_mode.rs`, plus `RoundedMode` in `theme/radius.rs`) — bytes derive from declaration discriminants (`Variant as u8`, list variants in data-crate declaration order) and are a transient in-process cache encoding only; persistence goes through the serde wire strings. Both keep unknown input from silently falling through (label fallback / defensive byte fallback).

## Theme System

- `ThemePalette` includes a serde-default `border` hairline color (empty string → runtime derives it by darkening `background.hard` 30 %)
- `config.toml` stores `theme = "name"` — points to `~/.config/nokkvi/themes/{name}.toml`

## Domain Types (`data/src/types/`)

Iced-free. Key types:
- `TrawlCrate` / `TrawlBlend` (Interleave/Weighted/ShuffleAll) / `TrawlRatingFilter` (star-threshold + `Unrated`) + the pure `blend_trawl()` engine (`trawl.rs`) — Trawl mix-builder domain, resolved via `LibraryOrchestrator::resolve_trawl`
- `LibrarySearchResults` (`library_search.rs`) — five typed groups (artists/albums/songs/genres/playlists) returned by `AppService::search_library`, backing the Harbour whole-library search
- `ReactiveProperty<T>` / `ReactiveVecProperty<T>` (`reactive.rs`) — thread-safe shared property with subscribe-on-change
- `smart_criteria.rs` — the `.nsp` smart-playlist rule model: `CriteriaNode` (nested AND/OR groups) / `RuleLeaf` / `FieldRegistry` + `parse_nsp_envelope` (`NSP_MAX_BYTES` guard). The rules editor sources field values from `tags_api` / `TagsApiService`; authoring writes back to Navidrome via the playlists API (no local `.nsp` persistence)

## API Patterns

- **Star**: optimistic UI + revert on failure, both through `starred_flag_message`, which only sets the flag. A refused star or rating also toasts the error, because the optimistic toast is already up: `star_result_message` / `rating_result_message` chain the revert behind it (`ToastMessage::PushThen`). A song's love rates five stars only once the server has taken the star: `star_result_message`'s Ok arm sends `SongLoved`, whose handler rates locally through `handle_song_rating_updated` and on the server, so a refused love or unstar never rates. Albums, artists and playlists have no love path
- **Rating**: +/- hotkeys
- **Playlist CRUD**: Navidrome-native REST (not Subsonic) for writes
- **Subsonic reads**: `subsonic_get_envelope` is lenient (never looks at the HTTP status or a `status: "failed"` envelope, so a failure can read as an empty list) and is kept only for the public `getOpenSubsonicExtensions` probe, where an empty list is fail-safe; every other read uses `subsonic_get_envelope_checked`, which runs `check_subsonic_response_status` first. That check is shared with the Subsonic writes (`subsonic_post_ok`: star, rating, playlist and radio edits, the play-queue save) and the scrobble GETs (`send_scrobble`, which types the outcome as `ScrobbleError`: `SessionRejected` drops to login, `Refused` is not sent again for that play, `Failed` retries), and maps HTTP 401 and a failed envelope with code 40 (a rejected token arrives as HTTP 200 + code 40), 41 (token auth switched off), 42 (the mechanism switched off) or 44 (invalid or revoked API key) to `NokkviError::Unauthorized`, so the UI drops to login, where a fresh login sets up a working credential; every other failed envelope (43, a key sent beside another credential, included) is a plain error. Code 40 is only a dead session when the credential itself is well-formed: `subsonic_token_credential` (`services/auth.rs`) form-encodes the username, and `resume_session` re-encodes a credential stored raw before that fix. A new Subsonic read uses the checked one: an empty answer gets acted on as fact (a playlist played or edited as empty, a library selection pruned to nothing)
- **Native list reads**: `load_genres_with_libraries` and `load_playlists_with_libraries` error like the paged album / artist / song loaders (a failed request, a 401 as `NokkviError::Unauthorized`, an unparseable body); the views' shared `handle_loaded_with` drops a 401 to login and toasts anything else with the rows kept, and the Save Queue and Add to Playlist pickers map a failure through `playlists_fetch_failed_message` (the entity and batch add path keeps `map_add_to_playlist_result`). Only the Subsonic genre-count enrichment stays lenient (blank counts). `parse_json_or_default` is for reads where empty is fail-safe (collage lists, the orphan sweep's raw playlist list), never for a list a view shows
- **Artist info**: `artist_info_api()` → `getArtistInfo2` (`services/api/artist_info.rs`, checked reader, `count=0`), returning the iced-free `ArtistInfo` (`types/artist.rs`); empty strings read as `None`. The call is what makes Navidrome run its agents for an artist, and it refreshes info past its 24 h time-to-live in the background
- **MPRIS**: D-Bus background task; full metadata for both queue songs and radio streams
- **Tray**: ksni-based StatusNotifierItem in `src/services/tray.rs`; emits `TrayEvent` to the UI
- **Internet Radio**: Subsonic `getInternetRadioStations` + mutative CRUD tasks
- **Radio scrobbling** (`services/radio_scrobble/`): direct-to-service ListenBrainz + Last.fm submission for internet-radio plays (radio tracks have no Navidrome id, so the Subsonic `/rest/scrobble` relay is unusable). `parse.rs::clean` strips ICY NUL padding and whitespace (the UI splits `Artist - Title` into `ScrobbleTrack::from_icy`); `lastfm.rs` handles MD5 `api_sig` signing + the 3-step browser-auth session flow; `source.rs` resolves creds by precedence env var → `config.toml [radio_scrobble]` → legacy redb (the Last.fm session key + username stay in redb). Iced-free; driven per playback-state update by the UI's `handle_radio_scrobble_tick` through its own `RadioScrobbleState` (wall-clock listen time; streams have no duration). A Last.fm session works only with the API key that minted it: `set_lastfm_credentials` clears it when the effective key changes, and `dispatch_radio` clears it on error 9 (`lastfm::is_invalid_session`) and sets `RadioSubmitOutcome::lastfm_session_dropped`, the one radio-scrobble failure the UI toasts
- **RadioArtStore** (`services/radio_art_store.rs`): bounded (entry-count + total-bytes LRU), server-URL-namespaced bincode blob under the shared `StateStorage` redb (key `RADIO_ART_INDEX`) remembering logo-less stations' last ICY now-playing art; stations with an admin `coverArt` logo are never persisted
